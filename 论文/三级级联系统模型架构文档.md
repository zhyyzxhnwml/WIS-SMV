# 三级级联系统模型架构文档

> 项目：船舶交通流智能体违规判断系统（智海巡航 / WIS-SMV）
> 本档回答：**这套三级级联由什么组成、每级做什么、级与级之间的契约是什么、怎么部署**
> 文档状态：v1.0（2026-10-16）
> 全部结论均给出代码位置（`路径:行号`），可直接按行号核对。

---

## 一、术语与范围

| 术语 | 含义 |
|---|---|
| **级联（cascade）** | 三级接力：便宜的层先跑，把「规则吃不下的部分」交给更贵的层 |
| **L1 规则加速器** | 确定性几何/法规规则，毫秒级、零 LLM 成本、结论可复算 |
| **L2 ML 门控** | LightGBM 四分类 + 门控判据，微秒级，决定「这条船值不值得花 LLM」 |
| **L3 大模型终裁** | 本地 LLM（Ollama）对疑难样本做语义级判定，秒级、有 token 成本 |
| **候选事件（CandidateEvent）** | L1 输出的「疑似违规片段」，带实测量值与证据点 |
| **门控（gate）** | L2 里那句「要不要调 L3」的判断，是本系统成本的主开关 |
| **证据链** | 从几何实测 → 规范码 → 法规条款引用的可追溯字段链 |

**范围界定**：本档只描述**级联本体**（L1+L2+L3+编排）。
Web 界面（`frontend/`）、对话智能体（`shipclaw/`）、插件运行时（`plugin_runtime/`）、
实验与评测脚本（`benchmark/`、`experiments/`、`论文/`）属于**周边**，只在它们与级联有契约的地方提及。

证据：各级包的自我声明 `ais_accelerator/__init__.py:6`、`triage_engine/__init__.py:2`、`llm_layer/__init__.py:2`；
编排器 `orchestrator.py:37`。

## 二、系统总览

```

   原始 AIS CSV ───────►│  run.py  process_file()  逐船循环              │
  (mmsi/时间/经纬度/    │  ① convert_csv  列名与时间口径归一             │

                        │     派生：航道 / 流场 / 时空索引 / 追越让路关系 │
                        └───────────────┬──────────────────────────────┘
                                        │ 每一条船
        ┌───────────────────────────────┼───────────────────────────────────────────┐
        │                               ▼                                           │
        │  ┌──────────── L1 规则加速器（毫秒/船，0 次 LLM）─────────────┐             │
        │  │ 质量体检 → 分段 → 检测(规则) → 合并 → 压缩 → 标注          │             │
        │  │ 产出 AnnotatedTrack：候选事件 events[] + 28 维特征向量      │             │
        │  │      └─ 每条事件带 features(实测量值) + evidence_points     │             │
        │  └───────────────────────────┬───────────────────────────────┘             │
        │                              ▼                                             │
        │  ┌──────────── L2 ML 门控（微秒/船，0 次 LLM）──────────────┐              │
        │  │ LightGBM 四分类(normal/obvious_issue/has_risk/needs_review)│             │
        │  │ risk_score = max(非正常三类概率)                          │              │
        │  │ 门控判据：证据强度优先（n_events==0 才送 L3）/ 风险分回退   │              │
        │  └──────────┬────────────────────────────────┬─────────────┘              │
        │    needs_llm=False│                          │needs_llm=True               │
        │                  ▼                          ▼                            │
        │   ┌───────────────────────┐   ┌──────────────── L3 大模型终裁 ────────┐   │
        │   │ _verdict_without_llm  │   │ LLMHandler.analyze(annotated,routing)│   │
        │   │ 用 L1/L2 结论，标注     │   │ 4 套 prompt 模板按 routing 选择       │   │
        │   │ llm_skipped=True      │   │ 输出 JSON：violation_detected / type /│   │
        │   │ prompt_template=      │   │ confidence / risk_level / 反馈字段    │   │
        │   │       "gated_skip"    │   │ 解析失败 → fail-closed（交人工复核）  │   │
        │   └───────────┬───────────┘   └───────────────┬──────────────────────┘   │
        │               └───────────┬───────────────────┘                          │
        │                           ▼                                              │
        │   编排层物化：violation_code / violation_subtype / violation_metric      │
        │              regulation_ref（法规条款引用）/ violation_event（事件描述）    │
        │                           ▼                                              │
        │   风险引擎 assess_risk → 插件 run_adjudicators（只能升风险，不能改结论）  │
        │                           ▼                                              │
        │   落库 detection_results（含 detection_source：谁立的判断）              │
        └──────────────────────────────────────────────────────────────────────────┘
```

一句话概括数据流：**L1 把轨迹变成「候选事件 + 28 维向量」，L2 决定要不要花钱，L3 只对疑难样本做语义判定，编排层把判定物化成可追溯的规范码与法规条款。**

证据：`run.py:351`（`process_file` 主循环）、`run.py:443`（L1 调用）、`run.py:485`（L2 调用）、
`run.py:547-558`（L3 与跳过分支）、`run.py:612`（风险引擎）、`run.py:648`（插件）、`run.py:672`（落库）。

## 四、L1：规则加速器（`ais_accelerator/`）

### 4.1 输入与处理阶段

- 输入：归一化后的 AIS 表（列：`mmsi / 时间 / 经度 / 纬度 / 航向 / 船首向 / 航速`），`run.py:convert_csv` 负责列名与时间口径转换（`run.py:248`）。
- 阶段：**质量体检 → 分段 → 规则检测 → 事件合并 → 轨迹压缩 → 标注**，由 `AcceleratorPipeline.annotate_track()` 串起来（`ais_accelerator/pipeline.py:357`）。
- 对外外观：`AISAccelerationFacade.annotate_track / annotate_file`（`ais_accelerator/facade.py:85-91`）。

### 4.2 输出契约（L1 → 下游）

`AnnotatedTrack`（Pydantic，`ais_accelerator/models.py:266-303`）字段：
`mmsi / ship / annotations / track / segments / events[] / feature_vector / feature_metadata / quality_report / raw_track / pipeline_metrics / processed_at`

交给 L2/L3 的序列化入口是 `AnnotatedTrack.to_agent_input()`（`models.py:313-328`），耗时统计走 `PipelineMetrics.summary()`（`models.py:252-263`）。

### 4.3 候选事件 `CandidateEvent`

`ais_accelerator/models.py:159-172`：

| 字段 | 含义 |
|---|---|
| `event_id / mmsi / start_time / end_time` | 标识与时间窗 |
| `candidate_type` | 候选类型（15 种，见 §4.6） |
| `related_types` | 关联类型（如同一段既像追越又像让路） |
| `zone_id / zone_name` | 命中的区域（来自规则库） |
| `priority` | 优先级（默认 `middle`） |
| `features: Dict` | **实测量值**：`cri / dcpa_nm / min_distance_nm / gap_minutes` 等 —— 证据链的几何端点 |
| `evidence_points: List[AISPoint]` | 证据点原始轨迹点 |
| `quality_issues` | 该片段继承的数据质量问题 |
| `source_event_ids` | 合并来源（事件合并阶段产生） |

### 4.4 28 维特征向量（`FEATURE_NAMES`，`annotator.py:340-372`）

| 组 | 维度 | 内容 |
|---|---|---|
| 数值特征 | 16 | 原始点数、标注数、critical/warning/info 标注数、标注置信度均值/最大/最小、总时长、速度方差、平均/最大/最小速度、改向次数、AIS 间隔次数、位置跳变次数 |
| 扩展特征 | 6 | 规则命中数、事件数、重叠标注数、分段数、质量问题数、重复点数 |
| 碰撞风险 | 6 | 碰撞风险事件数、最大 CRI、最小 DCPA(nm)、最小 TCPA(min)、平均相对速度、邻近船数 |

另有 5 项**不进向量**的附加元数据（`annotator.py:475-484`）：`overtaking_count / wrong_way_count / anchoring_out_of_bounds_count / give_way_count / illegal_towing_count`。

### 4.5 质量报告

`QualityReport`（`models.py:131-146`）：`mmsi / original_points / retained_points / duplicate_points / invalid_points / issues[]`，
属性 `level ∈ {good, fair, poor}`（`models.py:139`）；
`QualityIssue`：`code / severity / message / timestamp / details`（`models.py:84-89`）。
质量等级会一路传到 L3 的 prompt（`{quality_summary}`）与输出字段 `data_quality_level`。

## 五、L2：机器学习门控（`triage_engine/`）

### 5.1 模型与输出

- 算法：**LightGBM 四分类**（`objective=multiclass, num_class=4, boosting_type=gbdt`，`triage_engine/model.py:79-95`），
  模型文件 `triage_model.txt`（约 1.2 MB）+ `triage_model.txt.meta.json`。
- 类别：`LABELS = ["normal", "obvious_issue", "has_risk", "needs_review"]`（`model.py:43`）。
- 特征契约：**64 维**（meta 里前 28 个具名，其余 `reserved_0..35`）；补齐/截断在 `model.py:249-262`。
  23 维窗口特征写入 `reserved_0..22`、`has_w` 标志写 `reserved_23`（`triage_engine/window_feat.py:43-45,110-123`，生产调用点 `run.py:474`）。
- 输出 `RoutingDecision`（`triage_engine/router.py:89-163`）：
  `ml_category / ml_confidence / risk_score / all_probs / routing / needs_pgvector / needs_milvus / needs_llm / pgvector_hits / milvus_hits` 等。
- **风险分定义**：`risk_score = max(p_has_risk, p_obvious_issue, p_needs_review)`（非正常三类概率最大值，`router.py:63,227-230`）。
- 置信度阶梯：`HIGH=0.90 / MEDIUM=0.70 / LOW=0.50`（`router.py:39-41`），决定 `routing` 标签与是否做相似检索。

### 5.2 门控：成本的主开关（**本架构最关键的 20 行**）

门控在置信度阶梯之后**覆盖**「要不要花 LLM」这件事（`router.py:285-303`），两条判据：

| 优先级 | 判据 | 规则 | 依据 |
|---|---|---|---|
| **判据一（优先）** | **L1 证据强度** | `needs_llm = (n_events == 0)`：规则**一条候选事件都没报**（= 规则盲区）才送 L3；报了事件说明规则已给出判断，不再花钱 | `router.py:300-301` |
| 判据二（回退） | 风险分 | `needs_llm = risk_score >= RISK_GATE_THRESHOLD`（`RISK_GATE_THRESHOLD = 0.000880`） | `router.py:86,302-303` |

代码里直接记录了两种判据的实测对比（注入集 240 船，零额外 LLM 成本）：

| 场景 | 风险分判据（旧） | 证据强度判据（现役） |
|---|---|---|
| 完整规则 | 64.3% F1 @ 240 次调用 | **100% F1 @ 65 次调用** |
| 摘掉让路规则 | 64.3% @ 240 | **67.4% @ 78** |
| 摘掉追越规则 | 64.3% @ 240 | **79.4% @ 106** |

出处：`triage_engine/router.py:289-297` 的注释（原始设计脚本 `reproduce/gate_design.py`）。
**设计理由**：门控真正该问的是「规则层对这条船有没有把握」，而 `risk_score` 学的是「这条轨迹有多少个点」——
实测它与违规反相关（消融表中 L2 风险分 AUC 0.244/0.305，**低于随机**）。

运行期开关：`GATE_MODE`（默认 `evidence`，可切 `risk` 回退），调用点 `run.py:484`。

### 5.3 相似检索（可选支路）

`needs_pgvector` → `cases` 表向量检索（`router.py:305-310`）；`needs_milvus` → 轨迹序列向量召回（`triage_engine/milvus_client.py`）。

## 六、L3：大模型终裁（`llm_layer/`）

### 6.1 对外接口

- `LLMHandler.analyze(annotated_track, routing, max_track_points=200)`（`llm_layer/handler.py:352`）——**L3 的唯一入口**。
- 包级导出 `LLMHandler`、`PROMPT_TEMPLATES`（`llm_layer/__init__.py:22-27`）。
- 辅助：`violation_vocab()`（`handler.py:135`）、`_quality_level_of()`（`handler.py:158`）。

### 6.2 Prompt 体系

| 模板 | 用途 | 触发（`routing` → 模板映射，`router.py:129-137`） |
|---|---|---|
| `fast_confirm` | 快速确认 | 高置信度、有明确候选事件 |
| `careful_review` | 仔细复核 | 中等置信度 |
| `needs_review` | 完整审查 | 低置信度 / 需要全面检索 |
| `quick_verify` | 快速校验 | 其余轻量场景 |

模板定义在 `llm_layer/prompts.py:339-346`；单个 `fast_confirm` 模板装入的内容见 `prompts.py:68-117`：
`event_summary / annotation_confidence / rule_hits / regulation_context / quality_summary / track_data / annotations / similar_cases`。

注入块（拼接进模板的规则约束）：
- `RISK_GRADING_STANDARD`（风险分级标准，`prompts.py:55-65`）
- `{violation_vocab}` 违规词表（`prompts.py:290-296`）
- `{triage_context}` / `{measured_evidence}` 判性依据（`prompts.py:309-336`）

渲染在 `_render_prompt()`（`handler.py:423-513`）。
**消息形态**：单条 user 消息（`HumanMessage(content=prompt)`，`handler.py:766-769`），**没有独立 system 角色**；
「人格/系统设定」只在对话智能体 `shipclaw` 侧使用，不参与检测判定。

### 6.3 输出契约（LLM → 编排层）

模板约定 L3 返回 JSON（`prompts.py:99-116`）：

```
violation_detected / violation_type / violation_label / confidence / risk_level
agrees_with_triage / disagreement_reason / final_assessment / recommended_action
feedback_for_ml { markings_were_helpful, missed_issues, false_positives }
```

handler 附加字段（`handler.py:385-395`）：`routing / latency_seconds / model / prompt_template / data_quality_level / data_quality_suspect`。

> **法规条款引用不由 L3 输出**：`regulation_ref` 由编排层物化（`orchestrator.py:591` 检索，`:596` 兜底 `FALLBACK_REG`），
> 规范码/细类/量值同样在编排层生成（`orchestrator.py:573-576`）。L3 只负责「判性」，
> 「引哪一条法规」由确定性检索保证可追溯。

### 6.4 解析与失败处理（fail-closed）

| 情况 | 处置 | 位置 |
|---|---|---|
| 返回带 markdown 包裹 | 剥壳后 `json.loads` | `handler.py:815-830` |
| 空回复 / 解析失败 | `_fail_closed`：`violation_detected=False` + `risk_unverified=True` + `recommended_action=manual_review`（**交人工复核，不静默放过**） | `handler.py:789-812` |
| LLM 不可用 | 返回 `risk_level="mid", risk_unverified=True, error="llm_unavailable"` | `handler.py:743-757` |
| 调用异常 | 同上兜底 | `handler.py:772-786` |

## 十一、已知问题与注意事项（写论文时不要踩）

1. **门控判据已切换，但实验表未同步**：生产代码现役是**证据强度判据**（`router.py:300-301`，`GATE_MODE=evidence`），
   实测 100% F1 @ 65 次调用；而实验文档里的「C 生产级联」臂仍是旧的**风险分判据**（240 次调用）。
   论文要写成本时，必须用「优化后」的工作点（见优化文档），否则会自相矛盾。
2. **L2 的风险分对违规没有排序能力**（AUC 0.244/0.305，低于随机），根因是训练特征以体量特征为主；
   它当前的正确用法是**回退判据**，不是主判据。
3. **`num_ctx` 不在生产代码里**：上下文长度由 Ollama 服务端环境变量决定（`OLLAMA_CONTEXT_LENGTH=8192`），
   传错会导致静默截断。实验脚本里是显式设置的（`reproduce/llm_arms.py:178`）。
4. **L3 输出不含法规条款**：`regulation_ref` 在编排层物化；写「模型引用法条」时要落到 `orchestrator.py:591-596`，别写成模型能力。
5. **插件只能升风险**：任何「插件改了违规结论」的说法都与代码不符（`registry.py:11-15`）。
6. **两个同名 `run_pipeline`**：`start.py:89`（生产 CLI）与 `experiments/paper2/eval_real_zones.py:150`（实验），别混用。
