## 一、三个可直接写进 Abstract 的主张

### 主张 1（违规判断）：规则感知的级联在本任务上**决定性**优于文献无监督异常检测器

评测：注入集 240 条合成船（120 违规 / 120 合规）。真值由场景设计给定，
并用**独立参照实现**（`benchmark/reference/colreg_ref.py`）回放校验最小会遇距离，
**不是**规则引擎自己的输出（不循环）。

| 方法 | AUC | oracle F1（上界） | @1%FPR 召回 | LLM 调用 |
|---|---|---|---|---|
| **我们的 L1 规则引擎** | — | **100%** | **100%（FPR = 0）** | **0** |
| Proximity（会遇距离） | 0.843 | 77.9% | 23.3% | 0 |
| LOF | 0.368 | 66.9% | 0.0% | 0 |
| iForest | 0.292 | 66.7% | 0.0% | 0 |
| DBSCAN | 0.376 | 66.7% | 0.0% | 0 |
| VAE | 0.383 | 66.9% | 6.7% | 0 |
| LSTM-AE | 0.378 | 66.7% | 3.3% | 0 |
| VAE-LSTM | 0.423 | 66.7% | 5.0% | 0 |
| Transformer-LSTM | 0.391 | 66.7% | 3.3% | 0 |

McNemar 精确检验（成对、逐船）：我们 vs 每个基线，**F1 差 +22.1 ~ +33.3 个百分点，
p 全部 < 1e-20**；配对自助 2000 次的 95% CI 下界最低 +17.3 pt，不含 0。

**本表最锋利的一行不是我们的 100%，而是文献方法的 oracle F1。**
8 个方法里 7 个的 oracle F1 恰好 = 66.7%，**这正好是"全判违规"的平凡分类器**
（正负各半时 2·0.5/(1+0.5) = 66.7%）。换句话说：给它们**在测试集上调好的最优阈值**，
它们也只能做到"全部报警"，连把违规排在合规前面的排序能力都没有（AUC 0.29–0.42，**低于随机**）。

**为什么会这样（这是本文一个可独立成立的机制性结论）**：违规行为在单船运动学上是**不异常**的。
被注入"违规"的场景恰恰是**没有做避让动作**的那些船（保向保速、直着开过去），
而"合规"场景才是做了转向/减速的船。单船运动学异常检测器因此把**合规船**判成异常——
方向反了。唯一超过平凡线的 `proximity`，它超线靠的是**会遇距离**这一维，
也就是我们规则引擎在用的同一个几何量。

### 主张 2（级联）：以近乎零的 LLM 成本达到最优质量，**帕累托支配**纯 LLM

注入集上把"谁来判"拆成 7 个臂，同一批船、同一份真值、同一次调用口径
（Ollama 实测 `prompt_eval_count` / `eval_count`，不是估算）：

| 臂 | 谁来判 | F1 | LLM 调用 | prompt token | 平凡线 |
|---|---|---|---|---|---|
| **A** | L1 确定性规则 | **100.0%** | **0** | **0** | — |
| B | L2 LightGBM 门控 | 66.7% | 0 | 0 | = 平凡线 |
| C | 生产链路 L1→L2→L3 | 100.0% | 240 | 344,337 | — |
| D | 原始轨迹 → LLM | 47.7% | 240 | 703,803 | **低于平凡线** |
| E | RDP 压缩 → LLM | 58.7% | 240 | 270,596 | **低于平凡线** |
| F | L1 标注 → LLM（跳过门控） | 64.3% | 240 | 1,208,212 | **低于平凡线** |
| G | FrugalGPT 式两级 | 73.1% | 240 | 380,053 | 略高于平凡线 |

（正负各半，**「全判违规」的平凡 F1 = 66.7%**。）

级联成本-质量前沿（门控阈值 τ 扫描，未过闸门用 L1 兜底）：

| τ | LLM 调用 | 调用率 | prompt token | F1 |
|---|---|---|---|---|
| ∞（纯 L1） | 0 | 0.0% | 0 | **100.0%** |
| 0.5 | 1 | 0.4% | 4,063 | **100.0%** |
| 0.3 | 15 | 6.2% | 63,772 | 98.8% |
| 0.1 | 83 | 34.6% | 364,397 | 88.5% |
| 0.001（≈全放行） | 240 | 100.0% | 1,208,212 | 64.3% |

**结论：曲线单调下降 —— 每多花一次 LLM 调用，质量就往下一格。**
在 100% F1 的工作点上，级联花 0~1 次调用；而纯 LLM 花 240 次调用只拿到 47.7~73.1%。
**级联在成本-质量平面上严格支配纯 LLM。**

关键方法学细节：前沿曲线用 F 臂（每条船都送 LLM）的**逐船判决**复现——
改变门控阈值只改变"调用哪几条"，不改变任何一条船的判决内容，所以曲线上的点互相可比，
且**不需要为每个工作点重新调 LLM**（零额外成本）。

> ⚠ **必须如实写的一条限制**：现役门控阈值 `RISK_GATE_THRESHOLD = 0.00088`
> 在注入集上的放行率是 **100%**，也就是说**它当前一次调用都没省**（表里 C 臂 240 次调用即为此）。
> 阈值是在别的数据集上标定的，跨域不成立。论文里应写成
> "门控阈值必须按目标域重标定"，并给出上表的扫描结果作为标定依据；
> 把 C 臂说成"省了成本"是错的。

### 主张 3（级联的独立价值与一处必须修的设计缺陷）

质疑："L1 在注入集上已经 100%，L2/L3 还有什么用？"
做法（**零额外 LLM 成本**，`reproduce/rule_coverage.py`）：把某一类违规**从 L1 的判定规则里摘掉**，
等价于"规则库里没有这条规则"，再看后两级能不能兜住。

| 违规类型 | 样本(正/负) | L1 召回(有规则) | L1 召回(规则摘掉) | L2 风险分 AUC | L3(LLM) 召回 | 级联(现役 L2 门控) | 门控放行率 |
|---|---|---|---|---|---|---|---|
| give_way_failure | 72/120 | 100% | 0% | **0.244** | **100%** | 100% | 100% |
| overtaking_violation | 48/120 | 100% | 0% | **0.305** | **20.8%** | 20.8% | 100% |

三条结论：

1. **L3（LLM）确实有独立价值**：规则没覆盖的类别，只有 LLM 能捞回来
   （让路失败 100%、违规追越 20.8%）。这是"为什么要级联"的硬数字，不是设计主张。
2. **L2 的风险分对违规没有排序能力**（AUC 0.244 / 0.305，**低于随机**）。
   根因是它的训练特征以「标注条数 / 点数 / 位置跳变」这类**体量特征**为主
   （`triage_model.txt` 的特征重要性排序可证），学的是"这条轨迹有多少个点"，不是违规语义。
3. **现役门控阈值在注入集上放行率 100%** → 它当前既不拦船、也不省钱。
   这既是缺陷（没有分流作用），也是运气（没把该抓的船挡在外面）。
   → 论文的**设计建议**：门控判据必须按目标域重标定；
   一个「全放行」的门控在成本上等于没有门控，而它的误判在别的域会直接吃掉召回。

> 这一条原本是**负结果**，现在已经**修好了**（见 `论文/优化文档/`）：
> 把门控判据从「模型风险分」换成「**规则层证据强度**」（L1 一条候选事件都没报的
> 才送大模型），三个规则场景**全部同时**赢成本与质量——
> 完整规则下从 **64.3% F1 @ 100% 调用** 变成 **100% F1 @ 27.1% 调用**。
>
> **但必须写明前提**：这个优势只在**规则覆盖良好**的域成立。真实数据上 L1 报掉
> 91% 的船，「无事件」的含义从「规则盲区」变成了「安静的船」——所以新判据在
> 规则覆盖差的域**不能单独使用**，必须与风险分门控组合、且阈值按域标定（尚未标定）。
> 论文里要把这一条写成**条件性结论**，不能写成普适结论。
