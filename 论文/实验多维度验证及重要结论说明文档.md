# 实验多维度验证及重要结论说明文档

> 项目：船舶交通流智能体违规判断系统（智海巡航 / WIS-SMV，「三级级联」）
> 本档回答：**这些实验结论各自在多少个互相独立的维度上被验证过、每条结论的成立边界在哪、写论文时哪两个口径不能混着用**
> 文档状态：v1.0（2026-10-16）
> 数字口径：全部取自各实验落盘的 JSON，**不重算、不补零**；代码类结论给出 `路径:行号` 供逐行核对。

## 一、本档定位（先说清楚它不做什么）

本档**不重复报分数**。完整表格在：

| 材料 | 内容 | 位置 |
|---|---|---|
| 实验文档（5 篇） | 需求 → 可行性 → 设计 → 结果 → 验证 | `论文/实验文档/` |
| 优化文档（4 篇） | 目的 → 设计 → 结果 → 验证 | `论文/优化文档/` |
| 自动汇总表 | 表 1–表 5（机器生成） | `论文/实验结果_汇总.md` |
| 显著性 | McNemar + 配对自助 CI | `论文/显著性检验.md` |

那两份「验证」文档（`实验文档/05`、`优化文档/04`）是**各自口径内**的自校验——它们证明「这批实验自己没算错」。
本档做的是**跨口径的横向验证**：把同一条结论拿到不同的数据集、不同的对手强度、不同的判据、不同口径下各测一遍，
只有**在所有维度上都不翻车**的结论才配写进论文，其余一律标上边界。

一句话分工：

```
实验文档/05  ── 这批实验内部可信吗（真值、评测集、计算、公平、稳健）
优化文档/04  ── 这轮改动可信吗（实现一致、兼容、退路、负结果、风险披露）
本档        ── 把所有结论横过来看：哪几条站得住、边界在哪、哪里口径打架
```

## 三、维度 A｜门槛敏感度扫描（证伪测试）

> 这是回应审稿人**「你这一堆门槛是不是照着测试集调出来的」**的唯一硬证据。
> 本节即《三级级联系统模型架构文档》§4.6 引用的那一段扫描结论。

### 3.1 设计

把**单个**门槛换成一串别的值（其余门槛保持生产值），在注入集上重跑：

- 若门槛是**照着测试集挑的** → 峰值必然孤零零挂在生产值那一点上，换到邻近值就该掉；
- 若门槛是**照着物理量/法规定的** → 邻近值同样能用，曲线在峰值附近是一个**区间**。

门槛的生产取值（全部带默认值，可核对）：
让路 `give_way_close_quarters_nm=0.2` / `give_way_alteration_degrees=30` / `give_way_speed_drop_knots=2.0`
（`ais_accelerator/config.py:195,208,209`）；
追越 `overtaking_unsafe_distance_nm=0.10` / `overtaking_speed_diff_knots=1.0`（`ais_accelerator/config.py:122,105`）。

### 3.2 结果（表 4）

| 门槛 | 生产值 | 扫描（F1 %，**粗体 = 生产取值**） |
|---|---|---|
| `give_way_alteration_degrees` | 30 | 5→58.0 · 15→89.9 · **30→100.0** · 45→97.6 · 90→91.6 |
| `give_way_close_quarters_nm` | 0.2 | 0.05→58.0 · 0.1→66.7 · **0.2→100.0** · 0.3→100.0 · 0.5→90.9 · 1→90.9 |
| `give_way_speed_drop_knots` | 2 | 0.5→92.4 · 1→100.0 · **2→100.0** · 3→100.0 · 5→91.3 |
| `overtaking_speed_diff_knots` | 1 | 0.2→100.0 · 0.5→100.0 · **1→100.0** · 2→99.2 · 5→75.0 |
| `overtaking_unsafe_distance_nm` | 0.1 | 0.02→75.0 · 0.05→76.9 · **0.1→100.0** · 0.2→90.2 · 0.5→82.8 |

**结论**：5 个门槛的峰值**全部**落在生产取值处或其紧邻位置，两侧下降。
注入集的负对照全程 100%（合规场景一个都没误报），所以曲线掉下来是**漏报**造成的，不是乱报造成的。

### 3.3 必须写进论文的保留意见

| 保留点 | 事实 | 正确写法 |
|---|---|---|
| 两个门槛的峰是**平台**不是尖点 | 减速门槛在 1/2/3 节上都是 100%；追越速差在 0.2/0.5/1 节上都是 100% | 写成「门槛位于一个**宽的稳健区间**内」，**不要**写成「恰好最优」 |
| 平台 ≠ 可以随便取 | 平台的物理含义是「这个门槛在此任务上不敏感」（该批场景里 1 节与 3 节减速落在同一侧） | 明说平台的解释，避免被读成「门槛无关紧要」 |

**维度 A 判据**：若门槛是过拟合产物，任一门槛的邻近取值都该出现断崖；实测没有任何一个门槛出现断崖 → **通过**。

## 四、维度 B｜真值独立性（禁止循环论证）

| 检查 | 做法 | 结果 |
|---|---|---|
| 真值来源 | 由**场景设计**给定：每条场景预先写明「该不该违规、违反哪一条、目标船是谁」 | ✅ |
| 独立对账 | `benchmark/reference/colreg_ref.py`（**与生产代码不共用**）回放每个场景，独立算出最小会遇距离 | ✅ |
| 对不上怎么办 | 与设计值不符的样本**直接丢弃**，不进评测集 | ✅ 实际丢弃 32 条隔离失败候选 |
| 生产规则的角色 | 只用于**判分**，不用于**造答案** | ✅ |
| 场景谱成对 | 10 类场景里违规/合规成对出现，避免「合规全是同一种」 | ✅ |

**跨口径交叉验证**：真值链条上有两个环节都不是我们写的规则引擎——
(a) 场景设计时人为给定「该不该违规、违反哪一条、目标船是谁」；
(b) `benchmark/reference/colreg_ref.py` 独立回放、独立算出最小会遇距离，与设计值不符的样本直接丢弃。

再加一条**反证**：本系统自己的规则层在真实数据上并不好看（L1 **报掉了 91% 的船**，`优化文档/03` §3.1）。
若真值是照系统输出编出来的，不会出现这种难看的数字。

**维度 B 判据**：真值必须可追到「不是我们写的」的环节。→ **通过**。

## 五、维度 C｜对比公平性

### 5.1 有没有让对手吃亏

| 可能的偏袒 | 我们的做法 |
|---|---|
| 不给对手调阈值 | 报 **oracle 阈值**（在评测集上调到 F1 最大），并标注这是**上界** |
| 让对手用错阈值方向 | 双向试探 + 混淆矩阵对账（自校验 C1） |
| 只给对手阉割特征 | 对手拿到**会遇距离**这一关键几何量（正是我们规则在用的量） |
| 训练集不足 | 对手用全部真船正常窗拟合（无监督方法的规矩） |

### 5.2 有没有让自己占便宜

| 可能的便宜 | 事实 |
|---|---|
| 我们偷偷调阈值 | **L1 没有可调阈值**，报了就报警，「部署即所得」——这是对我们最不利的口径 |
| 我们偷看答案 | 判据是固定物理/法规门槛，不依赖评测集 |
| 我们不花成本 | 成本列如实报 0 次调用 / 0 token |

### 5.3 对手分数低必须是可解释的

8 个对手在注入集上 AUC **0.29–0.42（7 个低于随机）**，如果不可解释就说明是我们把他们调差了。机制解释（可独立成立）：

> 被注入「违规」的场景恰恰是**没有采取避让动作**的船（保向保速直着开过去）；而「合规」场景才是做了转向/减速的船。
> 单船运动学上的「异常」就等于「在机动」→ 这类方法把**合规船**判成异常，**方向反了**。

唯一超过平凡线的 `proximity`（77.9%）之所以能超，是因为喂给它的那一维正是**会遇距离**——即我们规则引擎在用的同一个几何量。
「对手分数低是因为特征口径不对」这一条能自洽，**维度 C 通过**。

## 六、维度 D｜统计显著性

| 项 | 内容 |
|---|---|
| 检验 | McNemar 精确检验（成对、逐船）+ 配对自助 2000 次的 95% CI |
| 最强对手 | `proximity`：F1 差 **+22.1 pt**，CI **[+17.3, +27.4]**，b/c = 0/68，p = 6.78e-21 |
| 其余 7 个 | F1 差 **+33.1 ~ +33.3 pt**，CI 下界最低 **+27.7**，p ≤ 3.01e-36 |
| 关键读法 | `b` 列**全为 0**：没有任何一条样本是「对手判对我们判错」 |

**一条必须写进论文的读法警告**：
McNemar 检验的是「两者**错误模式是否相同**」。当评测集极度不平衡、或两边在大量样本上互有对错时，p 值会自然很小——
**这只说明两个方法「错的地方不一样」，不等于质量差距大**。
质量差距要看 **F1 差与它的 CI**：注入集上 CI 是 +17~+39 pt 且不含 0，那才是决定性差距（`论文/显著性检验.md` 已写明该警告）。

**维度 D 判据**：差值的 95% CI 不含 0。→ **通过**。

## 七、维度 E｜结论稳健性（跨场景 / 跨判据 / 跨标定方式）

这是本档最核心的横向维度：同一条「新门控更好」的结论，被拿到三个方向上各撞一次。

| 稳健性检查 | 做法 | 结果 |
|---|---|---|
| **换违规类型** | 分别摘掉「让路失败」与「违规追越」两类规则 | ✅ 新判据 S3 在三个场景（完整 / 摘让路 / 摘追越）**全部**不低于现役 |
| **换候选判据** | 同时测 7 个判据（S0/S1/S2/S3/S5/S6/S7） | ✅ **只有 S3** 在三个场景里全都赢；S2 在摘让路场景崩到 31.9%，S7 在摘追越场景掉回 64.3% |
| **换阈值标定方式** | S6 允许**用真值**把现役判据的阈值调到最优（作弊上界） | ✅ 即便给现役判据 oracle 上界，它仍不如 S3；且 **S3 是免阈值的**（没有任何需要标定的旋钮） |

**S3 三场景实测**（零额外 LLM 成本，复用 F 臂缓存）：

| 场景 | 现役 S1（风险分） | 新 S3（无候选事件才调） | 变化 |
|---|---|---|---|
| (a) 完整规则 | 64.3% F1 @ 240 次 | **100.0% F1 @ 65 次（27.1%）** | F1 **+35.7 pt**，调用 **−72.9%** |
| (b) 摘掉让路规则 | 64.3% @ 240 次 | **67.4% @ 78 次（32.5%）** | F1 **+3.1 pt**，调用 **−67.5%** |
| (c) 摘掉追越规则 | 64.3% @ 240 次 | **79.4% @ 106 次（44.2%）** | F1 **+15.1 pt**，调用 **−55.8%** |

**为什么必须「换候选判据」**：只试一个判据，赢了也不知道是判据好还是运气好；
7 个一起测，才能说清「**S3 是唯一稳健的那个**」。

**维度 E 判据**：换场景、换判据、换标定方式后结论方向不变。→ **通过**。

## 八、维度 F｜负结果可信性

优化里有两轮**没达标**（O5/O6），另外还查出并修掉了一个**静默 bug**。没达标的结论本身也要被验证——否则「改成好看的口径重算」是防不住的。

| 检查 | 做法 | 结果 |
|---|---|---|
| 是不是只试了一种做法就下结论？ | ❌ 不是。O5 把算好的几何量值喂进去，O6 把判定过程逐步写清——**两个方向都试** | ✅ |
| 是否给了公平的对照？ | ✅ O6 与「同一条规则用代码执行」直接对照：**70.6% vs 100%（且 0 token）** | ✅ |
| 结果是否如实写入结论？ | ✅ 明确写「⚠️ 未达 L1 水平 / 退化为平凡分类器」，不粉饰 | ✅ |
| 静默 bug 是否被主动查出？ | ✅ 解析器把 222/240 条正确回答记成漏报，抽查原始回答后**假结论作废重跑** | ✅ 见 §九 |

**被挡下的假结论长什么样**（这是本档最值得记的一条）：

| 臂 I（判据写成提示 → LLM） | 修复前（假） | 修复后（真） |
|---|---|---|
| 精确率 | 46.7% | **56.2%** |
| 召回 | **5.8%** | **95.0%** |
| F1 | 10.4% | **70.6%** |

它的危险之处是**失败方向一致**（全部记成「未检测到违规」→ 召回被系统性压低），
看起来像一个「真的变差了」的结论，**不抽查原始回答就会进论文**。

**维度 F 判据**：没达标的结论经过多方向穷举 + 公平对照 + 明确标注；静默 bug 被主动查出并作废重跑。→ **通过**。

## 九、维度 G｜实现与计算可信性

### 9.1 实现—仿真一致性（防「论文写着一个代码里不存在的策略」）

| 检查 | 做法 | 实测 |
|---|---|---|
| 真实调用 `route()` | 不是手写一遍判据，而是调用 `triage_engine/router.py` 的**真身**，逐船比对 `needs_llm` | **0 条不一致**（240 条全对），调用 **65/240 = 27.1%**，与仿真表 S3 完全吻合 |

门控判据的代码位置（可逐行核对）：

```285:303:triage_engine/router.py
        if n_events is not None:
            decision.needs_llm = int(n_events) == 0
        else:
            decision.needs_llm = decision.risk_score >= RISK_GATE_THRESHOLD
```

`n_events is not None` 走**判据一（优先）**：L1 一条候选事件都没报（规则盲区）才送 LLM；
否则走**判据二（回退）**：`risk_score >= RISK_GATE_THRESHOLD`（`= 0.000880`，`triage_engine/router.py:86`）。
运行期开关 `GATE_MODE`（默认 `evidence`，可切 `risk` 一键退回）在 `run.py:484`；
`run.py:480-483` 的注释里写明了收益（调用率 6.2%）与该判据的适用前提（只能在规则覆盖良好的域单独使用）。

### 9.2 向后兼容

| 检查 | 实测 |
|---|---|
| 不传 `n_events` 的行为 | 仍走风险分判据：`needs_llm=True`（risk_score=0.030300 vs 阈值 0.00088），与改动前**完全一致** |
| 其它调用点 | 新参数为**可选**，`orchestrator.py` 等旧调用点不传即走旧路径 |

### 9.3 自校验（程序自己盯自己，实际挡下的错误）

| 编号 | 机制 | 实际挡下了什么 |
|---|---|---|
| C1 | 从分数还原预测与落盘 `tp/fp` 对账 | 首次运行即发现「预测方向未知」，改为双向试探 |
| C2 | 断言 `_labels` 等于从真值算出的 y | 曾误把真值当预测 → 得出「所有方法 F1 = 100%」的荒谬结论，被挡下 |
| C3 | 样本数不一致直接停 | 防按位置贴分的**静默错位** |
| C5 | 成本从缓存全量重算 | 曾漏计 49 次调用 → 防「又便宜又好」的假象 |

### 9.4 解析器健壮性（挡住一个方向一致的假结论）

臂 I 首次跑出 召回 **5.8%**、F1 10.4%，看起来是「让模型执行规则反而更差」。
抽查原始回答发现：模型把提示里 JSON 示例的外层花括号**原样抄回**（`{{...}}`），解析器取「第一个 `{` 到最后一个 `}`」→ 非法 JSON → 按约定记「未检测到违规」。
**240 条里有 222 条是这种情况**，而这个 bug **不报错、只是把召回系统性压低**。

| 修复前后 | 精确率 | 召回 | F1 |
|---|---|---|---|
| 修复前（假） | 46.7% | 5.8% | 10.4% |
| 修复后（真） | **56.2%** | **95.0%** | **70.6%** |

污染范围核查：D/E/F/G/H 五臂解析失败 **0/240**；用新解析器重解其缓存，与旧结果**逐条比对 0 条不一致**。

> 附带发现：臂 G 重跑前后 F1 从 71.8% 变为 73.1%（`temperature=0`、`seed=0` 固定）。
> 原因是 Ollama `NUM_PARALLEL=2` 把请求放进不同批处理槽位，浮点累加顺序不同。
> **论文里应写明「本地推理在并行槽位下非严格确定性」，单次运行绝对值有 1~2 pt 抖动，但不影响结论方向。**

**维度 G 判据**：论文里的策略 = 代码里的策略；算出来的数 = 落盘的数。→ **通过**。

## 十、维度 H｜口径纪律（成本数必须写清它在数什么）

优化 O3 在真实数据（182 天 / 23,832 船-日）上的结果：

| 门控判据 | LLM 调用率 |
|---|---|
| **新：L1 无候选事件才调** | **6.2%** |
| 旧 A：合成模型 + 置信度阶梯 | 16.6% |
| 旧 B：真实模型 + 风险分阈值 | 17.3% |

→ 新门控成本降到旧门控的**约 36%（1/2.8）**。

**这个数到底在数什么（必须与它并排写）**：

```
调用率 = P(该船-日 L1 候选事件数 == 0)
```

分母取**当天文件里的全部船**（含一条事件都没报的），否则会把「安静的船」系统性漏掉、调用率被严重低估。
**这个数与真值无关**——它只统计「有多少条船会被送去调大模型」，不含任何判决质量，
所以它既不需要真值、也不需要调大模型就能算出来。

**与它并排写的适用前提**：新判据假设「L1 报了事件 = 规则层已经有把握」；
而真实数据上 **L1 报掉了 91% 的船**，所以「无候选事件」≈**「安静的船」**，而不是「规则盲区」。
**新判据不能在规则覆盖差的域单独使用**，必须与风险分门控组合、且组合阈值按目标域标定（尚未标定）。

**组合门控为什么不下定量结论**：算它需要历史级联产物，而现存产物的门控口径与当前口径不自洽
——`cascade_prod_newl2` 里存了 `needs_llm` 的 1,357 条中只有 **16.3%** 为 True，
而按风险分算 **93.9%** 都该过阈值（该批产物生成于门控标定之前）→ **拒绝据此下定量结论**。

> 这条验证的价值在于：**它挡住了一个看起来合理、实则建立在错误前提上的结论。**

**维度 H 判据**：报成本数必须写清它的定义、分母、「与真值无关」，并并排写出适用前提。→ **通过**。

## 十三、重要结论说明（每条都带成立边界）

### K1｜违规判断：规则感知的级联决定性优于文献无监督异常检测器

| 项 | 内容 |
|---|---|
| 关键数字 | 我们 100% F1；对手 oracle F1 ≤ 77.9%，其中 **7 个恰为 66.7% 平凡线**；F1 差 **+22.1~+33.3 pt**，CI 下界最低 +17.3，p ≤ 3.01e-36 |
| 支撑维度 | B 真值、C 公平、D 统计 |
| **成立边界** | 只在**注入集**（正负各半、单一水域、合成短轨迹）上成立；**不能外推到真实数据上的表现**（见 §十四 冲突 4） |
| 边界理由（可独立成立） | 单船运动学异常检测在本任务上**方向反了**：违规船恰恰是「没做机动」的那批 |
| 论文落点 | Results 5.1（表 1）+ Discussion「机制性解释」 |

### K2｜级联在成本-质量平面上严格支配纯 LLM

| 项 | 内容 |
|---|---|
| 关键数字 | 100% F1 的工作点上，级联花 **0~1 次**调用；纯 LLM 花 **240 次 / 1,208,212 token** 只拿到 **64.3%**；曲线**单调下降**，最优调用数为 0 |
| 支撑维度 | B、G、H |
| **成立边界** | 表里的「C 生产级联」臂用的是**旧风险分判据**（放行率 100%，等于没省），**不能**用它论证「级联省了成本」；写成本必须用优化后工作点（K4） |
| 论文落点 | Results 5.2（表 2 + 图 1/2） |

### K3｜级联的后两级有独立价值

| 项 | 内容 |
|---|---|
| 关键数字 | 把某类违规从 L1 规则里摘掉后 L1 召回 **0%**，L3（LLM）仍能捞回：让路失败 **100%**、违规追越 **20.8%** |
| 支撑维度 | E（换场景）**仅此一个维度** |
| **成立边界** | 单维度证据；L2 风险分对违规**无排序能力**（AUC 0.244/0.305，低于随机），所以「后两级」的价值实际由 **L3 单独承担** |
| 论文落点 | Results 5.3(b)（表 5） |

### K4｜门控判据从「模型风险分」换成「规则层证据强度」后，三场景全部同时赢成本与质量

| 项 | 内容 |
|---|---|
| 关键数字 | (a) 完整规则 **100% F1 @ 27.1% 调用**（现役 64.3% @ 100%）；(b) 摘让路 67.4% @ 32.5%；(c) 摘追越 79.4% @ 44.2% |
| 支撑维度 | C 公平（给现役 oracle 上界仍输）、E 稳健（三场景 × 7 判据）、G 实现（逐船一致）、H 口径（成本数写清定义与前提） |
| **成立边界** | **只在规则覆盖良好的域成立**。真实数据上 L1 报掉了 91% 的船，「无事件」≈「安静的船」而非「规则盲区」→ 新判据不能单独使用，必须与风险分门控组合、并按域重标定阈值（尚未标定） |
| 代价 | 100% F1 @ 0 次调用 → 100% F1 @ 65 次调用，**换来的不是质量而是「规则盲区被兜住」的可解释性**；S3 是**免阈值**的 |
| 论文落点 | Results 5.2 + Discussion「条件性结论」；代码 `triage_engine/router.py:300-301`、`run.py:484` |

### K5｜规则层的价值不只是「知道规则」，更是「可靠地执行规则」以及「零成本」

| 项 | 内容 |
|---|---|
| 关键数字 | 把同一条规则**明确写成提示**交给本地 7B 模型执行（臂 I）→ F1 **70.6%**、精确率 56.2%；**同一条规则用代码执行 → 100%、0 token** |
| 辅助证据 | 臂 H（几何算好再喂）召回冲到全场最高 **97.5%**、提示最省（F 臂的 1/7），但精确率 51.3% → **退化成平凡分类器**；六个 LLM 方案最好的 G 臂 73.1%，全部远低于 L1 的 100% |
| 支撑维度 | E 稳健、F 负结果、G 实现（解析器修复后才得到 70.6% 这个真值） |
| 论文落点 | Discussion（这是全文最锋利的一条系统性结论） |

### K6｜两轮没达标是机制性的，不是「提示没写好」

| 轮次 | 机制性原因 |
|---|---|
| O5 几何喂给 LLM（臂 H） | 给了算好的几何量值，模型仍无法像代码那样**严格执行数值比较** → 召回冲到 97.5%，但精确率只有 51.3%，退化为「几乎全判违规」 |
| O6 判据写成提示 → LLM（臂 I） | 把判定过程逐步写清，模型仍只做到 **70.6%**；而**同一条规则用代码执行是 100%、0 token** |

| 项 | 内容 |
|---|---|
| 支撑维度 | E（口径稳健）、F（负结果可信） |
| 论文落点 | Discussion「负结果与设计教训」，并作为「为什么需要确定性规则层」的论据 |

### K7｜判据门槛不是照着测试集挑的

| 项 | 内容 |
|---|---|
| 关键数字 | 5 个门槛峰值全部在生产取值处或紧邻位置，两侧下降；2 个门槛的峰是**平台** |

| **成立边界** | 写成「门槛位于一个**宽的稳健区间**内」；**不要**写成「恰好最优」；平台的物理含义要解释 |
