## 一、本档补充术语

| 术语 | 大白话解释 |
|---|---|
| **候选事件** | L1 规则引擎报出来的「这条船可能有问题」的条目。一条船一天可能报 0~116 条。 |
| **硬证据** | 候选事件里**参数过得了硬门槛**的那些——这时规则层敢下结论，不再是「疑似」。 |
| **规则盲区** | 规则库盖不到的违规类型。L1 一条事件都不会报，这就是它的能力边界。 |
| **零额外成本复现** | 用已经缓存好的大模型判决来试新策略。换策略只改变「调用哪几条」，不改变任何一条判决的内容，所以各策略严格可比。 |
| **口径** | 同一件事的统计方法。口径不同，数字不能直接比（本文踩过这个坑，见验证文档）。 |

## 二、优化 1：门控判据换成「规则层证据强度」

### 2.1 原理

门控真正该回答的问题不是「这条轨迹像不像异常」，而是：

> **「规则层对这条船，有没有把握？」**

- 规则层**敢下结论**（有硬证据）→ 不必花钱让大模型再看一遍
- 规则层**看过但没定性**（有候选事件、无硬证据）→ 边缘案例
- 规则层**什么都没看到**（零候选事件）→ **这正是它的盲区**，最该让大模型补位

### 2.2 策略空间（7 个方案一起测，让数据说话）

| 编号 | 判据 | 送大模型的条件 |
|---|---|---|
| S0 | 纯 L1 | 从不送（成本下界、质量参照） |
| S1 | **现役** | 风险分 ≥ 0.000880 |
| S2 | 证据强度 | 无硬证据 |
| S3 | **规则盲区** | **无任何候选事件** |
| S7 | 会遇链 | 没有被判出会遇链违规 |
| S5 | 全送 | 永远送（成本上界、质量参照） |
| S6 | 现役判据最优阈值 | 风险分 ≥ 在评测集上调到最优的阈值（上界） |

S1 与 S6 是**给现役判据的最好机会**（S6 允许偷看答案调阈值）。如果新判据还是赢，结论才站得住。

### 2.3 评测场景（三个，缺一不可）

| 场景 | 做法 | 为什么必须测 |
|---|---|---|
| (a) 完整规则库 | 原样评测 | 基准情形 |
| (b) 摘掉「让路失败」规则 | 把该类型事件当作不存在 | 模拟规则盲区——这才是门控真正要发挥作用的场合 |
| (c) 摘掉「违规追越」规则 | 同上 | 换一类违规，防止结论只对某一类成立 |

### 2.4 零额外成本复现的方法

大模型的逐船判决取 **F 臂缓存**（F 臂把**每一条船**都送进大模型，所以每条船都有一份独立意见）。

于是对任意门控策略：

```
该船被送 → 用大模型的意见
该船没被送 → 用免费那一级（L1 规则）的意见
```

**换策略只改变「调用哪几条」，不改变任何一条判决的内容** → 各策略严格可比，且**不需要为每个策略重新调大模型**。

### 2.5 落地设计（接口与退路）

| 项 | 设计 |
|---|---|
| 接口 | `TriageRouter.route()` 新增**可选**参数 `n_events`（L1 候选事件条数） |
| 向后兼容 | 不传 `n_events` 时**行为完全不变**（仍走风险分判据） |
| 一键退路 | 环境变量 `GATE_MODE`：`evidence`（默认，新判据）/ `risk`（退回旧判据） |
| 兼容旧调用方 | 其它调用点（如编排器）不传新参数即自动走旧路径 |

**为什么用「不传就保持原样」而不是「直接改」**：生产链路里可能有别的调用点，改默认值会让它们的行为静默变化。用可选参数 + 环境开关，风险最小。

## 三、优化 2：L1 洪泛类型抑制

### 3.1 原理

对每个事件类型算 **lift**：

```
lift(类型) = P(该类型出现在事故窗) ÷ P(该类型出现在正常窗)
```

- `lift ≈ 1` → 这个类型对「是不是事故」毫无信息
- `lift < 1` → 它更常出现在**正常**窗里，是**反向噪声**，不只没用还会盖住真信号

### 3.2 抑制策略（4 种，从温和到激进）

| 编号 | 做法 |
|---|---|
| P0 | 现役：所有类型都算报警 |
| P1 | 抑制 `lift < 1` 的类型 |
| P2 | 抑制 `lift ≤ 1.1` 的类型（更激进） |
| P3 | 只留 lift 排名前 4 的类型 |
| P4/P5/P6 | 直接抑制**报警量最多**的 1 / 2 / 3 类 |

**为什么还要做 P4–P6**：P1–P3 是按「信息量」筛，P4–P6 是按「数量」筛。两个角度都试，才能区分「洪泛是因为量大」还是「洪泛是因为反向」。

### 3.3 两种口径都报

- **松口径**：窗口内报了任何保留类型的事件
- **严口径**：窗口内有硬证据（过硬的判定门槛）

只报一种口径等于给读者看一半。

### 3.4 成本

**零**。全部在已有的 L1 逐日缓存上重算，不重跑 L1、不调大模型。

## 四、优化 3：新门控在真实数据上的成本与风险

### 4.1 为什么要单独做这一步

注入集的船是 **20 分钟合成短轨迹**，真实数据是**一整天轨迹**。L1 在两种数据上的事件分布完全不同：

| | 每船事件数 | 说明 |
|---|---|---|
| 注入集 | 中位 40（4 船 × 20 点） | 合成船为单窗口 |
| 真实数据 | 中位 **12**，均值 17.7，最大 116 | 一整天累积 |

所以**注入集上的调用率不能外推到线上**。必须直接在真实数据上算。

### 4.2 方法（不需要调大模型）

```
调用率 = P(该船-日 L1 候选事件数 == 0)
```

分母取**当天文件里的全部船**（含一条事件都没报的），否则会把「安静的船」系统性漏掉、调用率被严重低估。

### 4.3 关键的风险检查（这一步不能省）

```
事故船覆盖率 = P(该船-日 L1 报过事件 | 该船-日有锚点正样本)
```

**如果这个数很低，说明新门控把事故船全都挡在门外了** —— 省钱省在了最不该省的地方。所以必须同时报出来。

### 4.4 并集门控的定量尝试

理论上「无事件 **或** 风险分高」的并集判据能同时保住召回与成本。用已有的级联产物（含 `n_events` 与四类概率）可以算：

```
调用率(并集) = P(无事件 或 风险分 ≥ 阈值)
```

**但这一步有个前置条件**：历史产物必须是同一版门控口径下生成的。设计里明确要求先做**口径一致性检查**，不一致就**不下结论**（见验证文档）。

## 五、防自欺设计（这一轮特有的）

| 机制 | 防的是什么 |
|---|---|
| **实现—仿真一致性校验** | 防「仿真里换了个判据、代码里没换」或反之。逐船对齐，不一致就报错 |
| **向后兼容校验** | 防改动静默改变旧调用方的行为 |
| **给现役判据最好机会** | S6 允许风险分判据偷看答案调到最优，新判据还要赢才算赢 |
| **三种规则场景** | 防结论只对某一类违规成立 |
| **两种口径** | 防只报好看的那个口径 |
| **负结果照写** | 洪泛抑制若变差，如实记为失败 |
| **风险指标强制同报** | 报调用率必须同时报事故覆盖率 |
| **历史产物口径检查** | 防拿不同口径的产物做定量结论 |
