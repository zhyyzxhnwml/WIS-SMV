## 1. 一句话贡献（Abstract 骨架）

> 在**海事监管**这一高价值、低标注、对可追溯性有硬要求的领域，我们提出并实现了一个**三级异构级联**（确定性规则加速器 → 轻量 ML 路由器 → 本地 LLM 终裁）。相比任意单级（纯 LLM / 纯 ML / 纯规则），级联以**显著更低的 token 成本**达到**可比或更优**的违规判定质量，并在 LLM 缺席时**优雅降级**。我们公开一套**多水域人工标注**的基准与**完整证据链**输出协议，使每一判定都可回溯到特征/规则/法规条款。

三个可量化的主张：
1. **P1 成本-质量帕累托**：级联存在非劣（Pareto）前沿，相同成本下质量 ≥ 纯 LLM，相同质量下成本 ≤ 纯 LLM。
2. **P2 证据链可追溯**：LLM 判定可回溯到 L1 标记、L2 特征与法规条款（`regulation_ref`），人工复核效率显著提升。
3. **P3 优雅降级**：LLM 不可用时系统不中断，质量有界退化（有界下界），可用于运营连续性论证。

## 3. 核心组件设计（论文侧视角）

### 3.1 判定管线（复用现有三级级联）

```
原始 AIS 轨迹 CSV
   │
   ▼ L1  ais_accelerator（确定性，毫秒/船）
   │   质量清洗 → 分段 → 事件检测(超速/禁渔区/限制区/断点/航向异常)
   │   → 事件合并 → RDP压缩 → 规则预筛 → 22维特征 + AnnotatedTrack(证据链)
   ▼ L2  triage_engine（LightGBM 四分类，微秒/船）
   │   normal / obvious_issue / has_risk / needs_review
   │   → 置信度路由：≥0.90 direct_pass；0.70–0.90 fast_confirm；0.50–0.70 careful_review；<0.50 needs_review
   │   → pgvector 相似案例 + Milvus 轨迹相似召回（注入 prompt）
   ▼ L3  llm_layer（Qwen2.5:7B @ Ollama，秒/船）
       四级 Prompt 模板 + 法规注入(regulation_ref) + 记忆上下文
   ▼
   判定结果 + 置信度 + 建议 + 完整证据链（JSONL trace）
```

### 3.2 证据链协议（本文的原创输出，对齐 P2）

每条船最终输出一个可序列化 trace 对象，字段：

```json
{
  "mmsi": "412345678",
  "route": "direct_pass | fast_confirm | careful_review | needs_review",
  "llm_called": true/false,
  "llm_route": "fast_confirm | careful_review | needs_review",
  "tokens": {"prompt_tokens": 0, "completion_tokens": 0},   // 成本核算
  "latency_ms": 1234,
  "labels": {
    "llm_label": "normal",
    "ml_label": "has_risk",
    "final": "has_risk"
  },
  "evidence_chain": [
    {"kind": "rule", "module": "rules.py", "rule": "speed_limit", "detail": "avg_speed=14.2 > 12", "severity": 2},
    {"kind": "feature", "name": "speed_exceed_ratio", "value": 1.18},
    {"kind": "case", "source": "pgvector", "case_id": "case_1023", "similarity": 0.87},
    {"kind": "regulation", "regulation_ref": "渔业法第23条"}
  ],
  "llm_reasoning": "...",
  "final_assessment": "...",
  "recommended_action": "..."
}
```

- **人工复核界面**：每一条判定都可点开证据链，逐条「是/否认可」，反馈回流（复用 `pg_db.py` 的 `ml_feedback` 表思路）。
- **可追溯指标**：`trace 完整率`（证据链各环节是否齐全）、`复核效率`（人工确认判定所需平均时间 vs 无证据链）。

### 3.3 成本核算（对齐 P1，论文硬指标）

- 从 Ollama `/api/chat` 响应 `usage.prompt_eval_count / eval_count` 精确统计 token（不是估算）。
- 成本单位：**每千船判定成本** = Σ token × 单价（可按本地算力折算成 GPU-seconds / 或按 $/1K token 公开价）。
- 级联 vs 纯 LLM 的成本差，就是「ML 分流省下来的 LLM 调用」。

## 4. 数据与 Ground Truth（旧实验的硬伤，本文第一优先修复）

### 4.1 数据集

| 项 | 要求 |
|---|---|
| 来源 | **多水域**：至少 3 个不同区域（如禁渔区 / 限制区 / 港口锚地），每区域 ≥ 300 船 |
| 规模 | 目标 **≥ 1000 船**（旧实验仅 603 船 1 个 CSV，单薄） |
| 时间跨度 | 覆盖工作日/周末、白天/夜间（避免时段偏差） |
| 原始格式 | CSV（MMSI / 时间 / 经纬度 / 航速 / 航向），与 `data/input/` 现格式一致 |
| 预处理 | 去重、剔除航速非法值、轨迹少于 N 点的船剔除（规则与加速器 QC 一致） |

### 4.2 人工标注协议（防「LLM 教 LLM」）

- **双人独立标注 + 仲裁**：两人各自标注，不一致处由第三人仲裁。
- **标注类别**：与系统标签一致的四类 + 违规类型（非法捕捞 / 闯入限制区 / 超速 / AIS 中断 / 航向异常 / 正常）。
- **质量门槛**：仲裁后 Cohen's κ ≥ 0.70 才可用；κ < 0.70 的类别重新定义标注指南再标一轮。
- **盲标**：标注者看不到系统输出（避免锚定）。

### 4.3 数据划分（防泄漏，必做）

- **按船划分**（同一 MMSI 只落一个 split）：60 / 20 / 20 = train / valid / test。
- **分层抽样**：每个水域、每个违规类别按比例抽，保证 test 里稀有类别不消失。
- **分段时间**：train/valid/test 的时间窗不重叠（避免时间相关泄漏）。
- 训练 / 增量训练 / 调参**只用 train+valid**；**test 全程冻结**，仅最终评测时跑一次。

## 5. 基线（6 个，全部在**同一批标注数据**上评测）

| 编号 | 基线 | 实现 | 与级联对比点 |
|---|---|---|---|
| B1 | Raw-LLM | 原始轨迹直接喂 Qwen2.5（无加速器无特征） | 加速器的「压缩+特征」是否无损 |
| B2 | Compressed-LLM | RDP 压缩轨迹喂 LLM（跳过特征/规则） | 压缩是否够 |
| B3 | Annotated-LLM | 带标记(AnnotatedTrack)轨迹喂 LLM（跳过 ML 路由） | ML 路由是否省成本不减质 |
| B4 | ReAct-LLM | LLM + 工具调用（轨迹/法规查询）迭代推理 | 路由 vs 工具链成本/质量 |
| B5 | FrugalGPT-style | 级联式「先便宜后贵」多 LLM 级联（简化实现） | 异构级联 vs 同构级联 |
| B6 | ML-only | 只跑 LightGBM 路由，不调 LLM | 级联 vs 纯 ML（LLM 增量值） |

> 已有代码可快速搭出 B1–B3、B6（复用加速器/路由/LLM 各层单独跑）；B4 需 `shipclaw` 工具调用能力；B5 需二次 LLM 调用链（最费工，可作「尽力而为」基线，不达标也不影响主结论）。

## 6. 核心实验（5 个，对应论文 4–5 章）

### E1 端到端主对比（论文 Table 1）
- 6 基线 + 级联，在 test 上报告：**准确率 / 宏-F1 / 召回率（违规类） / 每千船成本 / 平均时延**。
- 统计：**McNemar 检验**（成对、逐船）判断级联 vs 各基线准确率差异是否显著；**paired bootstrap 95% CI**（1000 次重采样）给 F1/成本差区间。
- 成本-质量散点图：x=每千船成本，y=宏-F1，每个系统一个点 → 主图（见 §8 图表清单）。

### E2 置信度阈值扫描（路由成本旋钮）
- 对 HIGH/MEDIUM/LOW 阈值做**网格扫描**（如 HIGH ∈ {0.80,0.85,0.90,0.95}），画**帕累托前沿**：阈值越高 LLM 调用越少、质量越低。
- 报告最优操作点（在满足 F1 下界约束下成本最低的阈值组合）→ 直接回答「系统该把旋钮拧到哪」。

### E3 证据链可追溯性（对齐 P2，领域特色）
- 用户研究或代理指标：给定判定 + 证据链 vs 仅判定，人工复核**准确率**与**耗时**。
- 定量指标：`regulation_ref 引用准确率`（抽检 LLM 引用的法规条款是否真匹配）、`trace 完整率`。

### E4 数据规模消融（对齐「数据单薄」问题）
- 用 train 子集（如 25% / 50% / 75% / 100%）训练 L2 路由，画**数据规模 → 级联质量/成本**曲线。
- 回答：在没有大标注集的海事场景，级联相对纯 LLM 的优势是否随数据量收缩而扩大（弱监督 + 规则兜底的价值）。

### E5 组件消融（对齐 DESIGN.md 里的消融清单）
| 消融 | 去掉什么 | 预期 |
|---|---|---|
| 去规则预筛 | L1 rules | 特征噪声↑，L2 质量↓ |
| 去相似案例召回 | 关掉 pgvector/Milvus 注入 | 模糊 case 质量↓ |
| 去法规注入 | 关掉 regulation_ref | 引用准确率↓ |
| 去记忆上下文 | 关掉 memory 注入 | 趋势类判定↓ |
| 无反馈闭环 | 不增量训练 | 长期质量不升（可选，时间允许） |

## 7. 统计与防自欺清单

- ✅ 独立人工 GT（不循环 LLM）
- ✅ 按船分层、分时防泄漏划分
- ✅ 成对检验（McNemar / paired bootstrap），不只用点估计
- ✅ 报告 95% CI，不只报均值

## 11. 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| 级联不显著优于 B1（纯 LLM） | 中 | 主卖点退到「成本节省」而非「质量提升」；帕累托前沿保证非劣即可成文 |
| 标注 κ 达不到 0.70 | 中 | 缩小类别粒度 / 重写标注指南 / 扩大标注样本直到一致 |
| 海事数据合规/获取难 | 中 | 用公开 AIS 数据集（如 MarineCadastre）合成多水域；标注按类别抽样 |
| 反馈闭环效果弱（旧实验 +1.93%） | 高 | **不在主实验承诺**，只做扩展讨论；主线是成本-质量帕累托 |
| 阈值扫描全 +0.00%（旧实验现象） | 高 | 根源是 GT 循环 + 数据单薄；修好 §4 后重跑；若仍不显著，如实报告为「成本无提升但质量无损」 |
| Ollama 竞态 / Milvus 陈旧连接污染结果 | 中 | 实验前跑 `health_check.py` 全链路自检；trace 记录每次 LLM 调用状态；失败样本标注重试 |
| 时间不够做 B4/B5 | 中 | 标注为「尽力基线」，缺这两个点不影响主结论 |

## 12. 一页纸总结（给导师/组会 30 秒版）

> **问题**：海事违规判定既要质量又要低成本，还要每条判定能追溯到依据。
> **方案**：三级异构级联——规则加速器过滤 + LightGBM 分流 + 本地 LLM 只判可疑子集，全链路 trace 证据链。
> **实验**：人工 GT（不循环 LLM）+ 6 个可比基线 + 成本-质量帕累托 + 证据链可追溯 + 优雅降级。
> **交付**：16 周 → 可复现系统 + 一篇领域系统论文。
