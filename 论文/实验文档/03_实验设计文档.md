## 一、本档补充术语

| 术语 | 大白话解释 |
|---|---|
| **对照臂（arm）** | 实验中的一种配置方案。同一批数据分别交给不同配置去判，比较结果。 |
| **消融（ablation）** | 把系统的某个部件拆掉再测，看分数掉多少，用以证明该部件有用。 |
| **门控 / 闸门（gate）** | 决定「哪些样本值得花钱调大模型」的开关。 |
| **风险分** | 机器学习模型输出的「这条船可能有问题」的分数。门控就是拿它跟阈值比大小。 |
| **阈值（threshold）** | 一条分数线。分数过线就报警/就送大模型。 |
| **配对样本** | 同一批样本上两个方法各给出一个判定。因为比的是「同一个东西上的两种做法」，所以要用**配对**统计方法。 |
| **自助法（bootstrap）** | 反复从样本里有放回地抽样，用重采样得到的分布估计「这个数字有多不准」。 |
| **平凡分类器（trivial classifier）** | 「不带脑子」的基准：永远答同一个类。正负各半时它也能拿 66.7 分（F1），是必须画的参照线。 |
| **负样本下采样** | 为了让正负比例好看，人为丢掉一部分正常样本。本文**不做**——它会让精确率虚高。 |

## 二、总体设计

三类实验，分别对应三个主张：

```
               ┌─ 基准 1：注入集（240 船，正负各半）
               │      用途：违规判断的主战场（真值由场景设计给定）
   实验对象 ───┼─ 基准 2：HawaiiCoast_GT（11,064 窗，144 正）
               │      用途：外部体检（第三方真实事故真值）
               │
               └─ 对照：8 个文献异常检测器 + 7 个「谁来判」对照臂
```

| 实验 | 回答什么 | 对应的主张 |
|---|---|---|
| **E1 违规判断对比** | 我们的系统 vs 8 个文献方法，谁判得准？差多少？显著吗？ | 主张 1 |
| **E2 成本-质量分析** | 级联在什么成本下拿到什么质量？比纯调大模型好在哪？ | 主张 2 |
| **E3 外部体检** | 文献报告的高分在真实基准上复现得出来吗？ | 主张 3 |
| **E4 消融与证伪** | 规则没用时后两级能兜住吗？门槛是不是照测试集调的？ | 主张 4 + 抗质疑 |

## 三、被测系统（三级级联）规格

| 层 | 模块 | 输入 | 输出 | 耗时量级 |
|---|---|---|---|---|
| **L1 规则加速器** | `ais_accelerator/` | 原始 AIS CSV（7 列：mmsi/时间/经度/纬度/航向/船首向/航速） | `AnnotatedTrack`：28 维特征向量 + 标注 + 候选事件 + 质量报告 | 毫秒/船 |
| **L2 机器学习筛查** | `triage_engine/` | L1 的 28 维特征（模型侧补齐为 64 维） | 四分类 + 各类概率 + 风险分 + 门控结论 | 微秒/船 |
| **L3 大模型终裁** | `llm_layer/` | L1 的标注轨迹 + L2 的路由决策 | 违规判定 JSON（是否违规/类型/置信度/依据） | 秒/船 |

**关键参数（可复现性必须写清）**：

| 项 | 取值 |
|---|---|
| L1 特征向量维度 | 28 |
| L1 候选事件类型 | 16 个规范码（含 `give_way_failure`、`overtaking_violation`、`speed_violation`、`ais_gap`、`illegal_towing` 等） |
| L2 模型 | LightGBM 四分类，64 个特征（前 28 个有名 + 36 个预留位） |
| L2 类别 | `normal` / `obvious_issue` / `has_risk` / `needs_review` |
| L2 置信度阶梯 | 高 0.90 / 中 0.70 / 低 0.50 |
| L2 门控阈值 `RISK_GATE_THRESHOLD` | 0.000880（判据 = 非正常三类概率的**最大值**） |
| L3 模型 | `qwen2.5:7b-instruct-q4_K_M`（Ollama，Q4_K_M 量化） |
| L3 采样参数 | `temperature=0`、`seed=0`、`num_predict=320`、`num_ctx=8192` |

**为什么门控读「非正常三类的最大值」而不是「最大类概率」**：最大类概率回答的是「模型对自己这个判断有多确信」，不是「这条船有多可能出问题」。实测前者与真实事故**反相关**（AUC 0.404，低于随机），后者正相关。这个细节不写清，审稿人会认为门控设计随意。

## 四、基准 1：注入集的设计

### 4.1 为什么要注入

真实 AIS 数据里**没有**「这条船违反了第几条」这种逐条标注。所以条款级评测只能靠**参数已知的合成场景**。

### 4.2 构造方法

1. 从真实轨迹文件里取船，作为每条场景的「宿主」。
2. 在旁边按**设计的相对运动**合成一条「本船」，使其与宿主形成指定几何关系：
   - **违规场景**：最近会遇距离压到危险值，且**不采取避让动作**（保向保速，或动作幅度小于门槛）。
   - **合规场景**：要么保持安全距离通过，要么做出足够大的转向/减速。
3. 用恒等式 `p_D(t) = p_H(t) + r(t)`（相对位置 = 宿主位置 + 相对位移）保证几何与宿主真实运动无关。
4. **独立参照实现回放校验**：`benchmark/reference/colreg_ref.py` 独立算出实际最小会遇距离，与设计值对不上就丢弃该样本。

### 4.3 场景谱（10 类，违规/合规成对）

| 场景 | 期望判定 | 数量（实际） |
|---|---|---|
| `gw_fail_clean` | 让路失败 | — |
| `gw_fail_marginal` | 让路失败（边缘） | — |
| `gw_fail_turn_short` | 让路失败（转向不足） | — |
| `gw_comply_turn` | 合规（转向避让） | — |
| `gw_comply_slow` | 合规（减速避让） | — |
| `gw_pass_safe` | 合规（安全通过） | — |
| `ot_fail_clean` | 违规追越 | — |
| `ot_fail_marginal` | 违规追越（边缘） | — |
| `ot_comply_wide` | 合规（宽距追越） | — |
| `ot_comply_turn` | 合规（追越中转向） | — |

**最终规模**：240 场景 = **120 违规**（72 让路失败 + 48 违规追越）+ **120 合规**。正负严格平衡。

### 4.4 判据门槛（在生产取值处）

| 门槛 | 生产取值 | 含义 |
|---|---|---|
| `give_way_close_quarters_nm` | 0.2 海里 | 构成「紧迫局面」的实测最近会遇距离 |
| `give_way_alteration_degrees` | 30° | 视为「已避让」的最小改向 |
| `give_way_speed_drop_knots` | 2 节 | 视为「已避让」的最小减速 |
| `overtaking_unsafe_distance_nm` | 0.1 海里 | 追越过程中的最小横距安全线 |
| `overtaking_speed_diff_knots` | 1 节 | 构成追越态势的最小声速差 |

## 五、基准 2：HawaiiCoast_GT 评测集的设计

### 5.1 评测单元

**20 分钟窗口**。正样本 = 真值里的船在其**报告时刻 ±1 小时**内的轨迹切片（取离报告时刻最近的至多 3 个窗）；负样本 = **同一天**其它在航真船的切片（每天上限 60 个）。

### 5.2 公平性控制（这些不是可选项）

| 控制项 | 做法 | 不这么做的后果 |
|---|---|---|
| 正负同日抽取 | 负样本只取正样本当天的船 | 「哪天船多」会变成判别信号 |
| 只取在航船 | 窗口内航速中位 ≥ 0.5 节 | 靠泊船航速≈0.1，基线只要看「动没动」就能分类 |
| 不用外边界当正样本 | 改用报告时刻做锚点 | 正窗里大半什么都没发生，标签本身没信息 |
| **不做负样本下采样** | 全部 10,920 个负样本都进评测 | 下采样会把正例占比从真实的 1.3% 抬到 33%，F1 虚高 |
| 时间口径按 UTC | 轨迹时间统一按 UTC 解释 | 本机时区 UTC+8 会让整天错位，正样本被静默丢掉 |

### 5.3 评测集规模

**11,064 窗（144 正 / 10,920 负），覆盖 182 天**；正例占比 1.30%，「全判异常」的平凡 F1 上限 = **2.57%**。

## 六、对照对象设计

### 6.1 8 个文献异常检测器（无监督）

| 方法 | 类型 | 说明 |
|---|---|---|
| `proximity` | 几何规则 | 只用「最近会遇距离」这一维，作为几何参照 |
| `lof` | 经典（局部离群因子） | 看一个点相对邻居有多孤立 |
| `iforest` | 经典（孤立森林） | 用随机切分把异常点「孤立」出来 |
| `dbscan` | 经典（密度聚类） | 落在低密度区的点算异常 |
| `vae` | 深度（变分自编码器） | 重构误差大 = 异常 |
| `lstm_ae` | 深度（LSTM 自编码器） | 同上，但能看时序 |
| `vae_lstm` | 深度（组合） | 变分 + 时序 |
| `transformer_lstm` | 深度（组合） | 注意力 + 时序 |

**统一约定（防止被质疑「你把他们调差了」）**：
1. 训练**只用正常样本**，不给任何标签——这是文献的标准用法。
2. 特征**不含绝对位置**，只用运动学特征 + 会遇几何。
3. 特征里**刻意不含**「报出航速与位置差分航速的差值」——那个差值在合成数据里是生成器指纹，会给基线偷分。

### 6.2 7 个「谁来判」对照臂

| 臂 | 谁来判 | 大模型调用 | 设计意图 |
|---|---|---|---|
| **A** | L1 确定性规则引擎 | 0 | 最便宜的一级，本身就是一个完整方案 |
| **B** | L2 机器学习门控 | 0 | 纯机器学习方案 |
| **C** | 生产链路 L1 → L2 → L3 | 只给门控放行的船 | 系统实际部署时的行为 |
| **D** | 原始轨迹（本船 + 邻近船）→ 大模型 | 全部 | 「直接调大模型」基线 |
| **E** | RDP 压缩轨迹 → 大模型 | 全部 | 压缩是否够（对应文献里的轨迹压缩思路） |
| **F** | L1 标注轨迹 → 大模型（跳过门控） | 全部 | 「把标注给它但不做分流」 |
| **G** | 两级式：先短提示粗判，不确定才升级到全轨迹 | 1~2 | FrugalGPT 式「先便宜后贵」的同构级联对照 |

**为什么 D/E/F 必须把邻近船一起喂进去**：违规住在**两船的关系**里（谁该让路、追越距离多少）。只给本船轨迹，再强的大模型也判不出来——那不是对比，是稻草人。所有臂都获得同一套信息：本船 + 窗口内 3 海里内最近的至多 3 条邻近船。

**RDP 压缩**：Ramer–Douglas–Peucker 折线简化算法，只保留形状关键点，容差 1e-4 度（约 11 米）。

## 七、指标设计

| 指标 | 含义 | 用在哪 |
|---|---|---|
| **精确率 P** | 报出来的里面有多少是真的 | 全部 |
| **召回率 R** | 真的里面抓到了多少 | 全部 |
| **F1** | 两者的调和平均 | 主指标 |
| **AUC** | 排序能力（0.5 = 瞎猜，<0.5 = 方向反了） | 全部 |
| **oracle F1** | 允许在测试集上挑最优阈值后的 F1 = **上界** | 给基线最有利的机会 |
| **@1%FPR 召回** | 「每 100 条正常船最多误报 1 条」这个诚实工作点上的召回 | 唯一不碰真值的可用口径 |
| **大模型调用次数** | 成本主口径 | 成本轴 |
| **prompt token / completion token** | 成本的细分；**Ollama 实测**，非估算 | 成本轴 |
| **时延（秒）** | 所有调用的墙钟时间之和 | 附注 |
| **平凡上限** | 「全判某一类」的 F1，作为参照线（注入集 66.7%，Hawaii 2.57%） | 全部 |

### 7.1 阈值口径（不允许含糊）

| 方法 | 用什么阈值 |
|---|---|
| 我们的 L1 | **没有可调阈值**，报了就报警——「部署即所得」 |
| 我们的 L2 门控 | 生产阈值 0.000880 |
| 文献基线 | 报**两个**：oracle（在测试集上调到最优，是上界）+ @1%FPR（用留出样本定档，不碰真值） |

**这是对我们最不利、对基线最有利的比法。** 如果这样还赢，结论才稳。

## 八、统计设计

| 检验 | 用途 | 具体做法 |
|---|---|---|
| **McNemar 精确检验** | 两方法在同一批样本上，错误模式是否有本质差异 | 记 b = 我们对、它错；c = 我们错、它对。在 H0 下 b ~ 二项分布(b+c, 0.5)，用组合数算双侧精确 p 值（样本量小时卡方近似不成立） |
| **配对自助 95% 置信区间** | 差值有多准 | 重采样**样本对** 2,000 次，取 2.5/97.5 分位 |
| **按天自助**（Hawaii 用） | 同一天的样本共享海况与船队，不能当独立样本 | 以「天」为重采样单位 |

**读 p 值的正确方式**：McNemar 检验的是「错误模式是否相同」。评测集极度不平衡时（如 Hawaii 的 144 正 / 10,920 负），两边在大量负样本上互有对错，b、c 都很大，p 值自然很小——这只说明两个方法**错的地方不一样**，**不等于**质量差距大。质量差距要看 **F1 差与它的置信区间**。

## 九、消融设计

### 9.1 门槛敏感度扫描（回应「门槛是不是照测试集调的」）

把**单个**门槛换成一串别的值（其余门保持生产值），在注入集上重跑，看 F1 怎么变。

- **判据**：如果门槛是照测试集挑的，峰值必然孤零零挂在那一个值上、换到邻近值就该掉；如果门槛是按物理/法规定的，邻近值也应该能用。
- **扫描范围**：每个门槛 5~6 个取值，共 25 组重跑。

### 9.2 规则覆盖消融（回应「L1 已经 100% 了，L2/L3 还有什么用」）

把某一类违规**从 L1 的判定规则里摘掉**（等价于「规则库里没有这条规则」），看后两级还能不能兜住：

- 该类的 L1 召回必然 = 0（构造出来的）
- 问 **L2 的风险分**还能不能把这类船排在合规船前面（AUC）
- 问 **L3（大模型）**能不能认出来（召回）
- 报**门控放行率**，看闸门有没有把该抓的船挡在外面

**这个消融零额外成本**：L3 的逐船判决直接复用 F 臂缓存。

### 9.3 级联成本-质量前沿（零额外成本的技巧）

用 F 臂（**每条船都送大模型**）的逐船判决来复现整条前沿：

- 风险分 ≥ 阈值的船 → 用大模型的意见（这才花钱）
- 其余船 → 用免费那一级（L1 规则）的意见

扫一遍阈值就得到完整的 (成本, 质量) 曲线。**换工作点只改变「调用哪几条」，不改变任何一条船的判决内容**——所以曲线上的点互相可比，且不存在「不同工作点用不同质量的意见」这种作弊。**零额外大模型调用。**

## 十、可复现性设计

| 机制 | 作用 |
|---|---|
| **逐条/逐日落盘** | 每完成一条（一次调用/一天/一个方法）就写盘，断电只丢正在做的那一条 |
| **缓存指纹** | 指纹 = 数据文件大小 + 特征版本号。对不上就自动重建，避免静默复用旧结果 |
| **固定随机性** | `temperature=0`、`seed=0`、数据集划分固定种子（如负样本对半切用 20261014） |
| **只读汇总** | 汇总脚本只读产物、不重算。缺哪个产物就把对应表标成「未完成」，**绝不补零** |
| **自校验** | 汇总时断言「从分数还原的预测」与落盘的混淆矩阵一致，对不上就报错而不是猜 |
| **列对齐自检** | 评测集与结果文件的样本数不一致时直接停下（按位置贴分会静默错位，只会给出一个看起来正常的错数） |
