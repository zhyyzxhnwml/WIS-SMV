# 实验验证文档

> 对应实验：《03_实验设计文档》E1–E4
> 目的：不是再报一遍分数，而是**逐条论证「这些分数凭什么可信」**
> 文档状态：v1.0（2026-10-15）

---

## 一、本档补充术语

| 术语 | 大白话解释 |
|---|---|
| **效度（validity）** | 「你测的真的是你以为在测的东西吗」。分构念效度、内部效度、外部效度、统计结论效度四类。 |
| **构念效度** | 指标是否真的反映了你想测的能力。例如「F1 高」是否真的等于「违规判断强」。 |
| **内部效度** | 因果推断是否干净。有没有别的因素（泄漏、时区、调参）在偷偷影响结果。 |
| **外部效度** | 结论能不能推广到别的场景（别的海域、别的船型、别的年份）。 |
| **统计结论效度** | 统计推断本身是否站得住（样本量够不够、独立性假设是否成立）。 |
| **自校验** | 让程序自己核对「我算出来的东西」和「落盘记录的东西」是否一致，对不上就报错而不是猜。 |
| **证伪测试** | 主动设计一个「如果我的结论是假的，就应该在这里露馅」的测试。 |

---

## 二、验证框架

把「可信」拆成五件事，逐条验证：

```
V1 真值可信 ── 标准答案是不是独立于系统、有没有对账
V2 评测集可信 ── 正负如何构造、时间口径对不对
V3 计算可信 ── 分数是怎么算出来的，有没有自校验
V4 对比公平 ── 有没有让对手吃亏、有没有让我们占便宜
V5 结论稳健 ── 换个门槛/换个零件，结论还成立吗
```

## 三、V1 真值可信性验证

### V1.1 注入集：真值不循环（对应需求 R4）

| 验证项 | 做法 | 结果 |
|---|---|---|
| 真值来源 | 由**场景设计**给定（每条场景预先写明：这条船该不该违规、违反哪一条、目标船是谁） | ✅ |
| 是否有独立对账 | 用 `benchmark/reference/colreg_ref.py`（**独立参照实现**，不共用生产代码）回放每个场景，独立算出实际最小会遇距离 | ✅ |
| 对不上怎么办 | 与设计值不符的样本**直接丢弃**，不进入评测集 | ✅ 实际丢弃了「合成船与其它船贴进 1.0 海里」的 32 条隔离失败候选 |
| 生产规则有没有参与 | 生产规则只用于**判分**，不用于**造答案** | ✅ |
| 场景谱是否成对 | 10 类场景里违规/合规成对出现，避免「所有合规都是某一种」的偏差 | ✅ |

## 四、V2 评测集可信性验证

### V2.1 有没有把评测集构造成「容易」的

| 潜在作弊手法 | 我们怎么做的 | 验证结果 |
|---|---|---|
| 违规场景挑容易的（动作幅度远小于门槛） | 场景谱里违规/合规**成对**：`gw_fail_clean` / `gw_fail_marginal` / `gw_fail_turn_short` 三档难度齐备 | ✅ 见《03_实验设计文档》§4.3 |
| 合规场景挑「什么都没做」的 | 合规侧覆盖**转向避让 / 减速避让 / 安全通过**三种正常处置 | ✅ 同上 |
| 正负比例被动手脚 | 正负**严格 1:1**（120 违规 / 120 合规），不下采样、不调比例 | ✅ |
| 用绝对位置当特征（可反推海域） | 基线特征**不含绝对位置**；我们的有监督筛查也一律不报含位置的版本 | ✅ 见 V4.3 |
| 合成船锚点作弊 | 用恒等式 `p_D(t) = p_H(t) + r(t)`，相对几何与宿主真实运动无关；与设计值不符的样本直接丢弃 | ✅ 实际丢弃 32 条隔离失败候选 |
| 用绝对位置当特征（可反推海域） | 基线特征**不含绝对位置**；我们的有监督筛查也一律不报含位置的版本 | ✅ 见 V4.3 |

### V2.2 平凡线算术核对

| 数据集 | 正例占比 p | 平凡 F1 = 2p/(1+p) | 实测 |
|---|---|---|---|
| 注入集 | 120/240 = 0.500 | 2×0.5/1.5 = **66.7%** | ✅ 与对手实际得分 66.7% 吻合 |

**这项核对的意义**：如果算错平凡线，就会把「和瞎报一样」的方法误读成「有点本事」。实测对手的 oracle F1 恰好落在算出来的平凡线上，反过来验证了算术没算错。

## 五、V3 计算结果可信性验证（自校验机制）

这一节记录的是**程序自己盯自己**的机制，以及实际发现并修掉的问题。

| 编号 | 自校验机制 | 防的是什么 | 实际结果 |
|---|---|---|---|
| C1 | 从 `_scores` + `oracle_threshold` 还原预测后，与落盘的 `tp`/`fp` **对账**；对不上就返回失败、不猜 | 方向搞反（`≥` 还是 `≤`）、数据错位 | ✅ 首次运行即发现方向未知，改为双向试探 + 对账 |
| C2 | 断言 `_labels` 逐条等于我们从真值算出的 y | **`_labels` 里存的其实是真值，不是预测**（命名有歧义） | ✅ 实际踩到并修正：一开始误当真值，得出「所有方法 F1 = 100%」的荒谬结论，被对账机制挡下 |
| C3 | 评测集与结果文件的样本数不一致时**直接停下** | 按位置贴分会**静默错位**，只会给出一个看起来正常的错数 | ✅ 已实现 |
| C4 | 按 `(天, mmsi, 起始时刻)` 三元组对齐，不按数组下标 | 评测集被裁剪后错位 | ✅ 已实现 |
| C5 | 成本统计**从缓存全量重算**，不在循环里累加 | 命中缓存的调用被漏计 → 成本被低估，得出「又便宜又好」的假象 | ✅ 实际踩到并修正：D 臂曾少算 49 次调用 |
| C6 | 事后核对「提示里的轨迹点数是否超过设定上限」 | 缓存里混入**不同参数设置**的旧记录（方法学瑕疵） | ✅ 核对通过：最大 80 行 = 4 船 × 20 点，与设定一致，无混用 |
| C7 | 缓存指纹包含数据文件大小 + 特征版本号 | 输入没变但代码变了，旧特征被静默复用 | ✅ 已实现 |
| C8 | 汇总脚本**只读产物**；缺哪个产物就把表标成「未完成」 | 把「还没跑」伪装成「跑了但很差」（补零） | ✅ 已实现 |

### V3.1 交叉一致性检查

| 检查 | 内容 | 结果 |
|---|---|---|
| 整体与逐条一致 | L1 船级二分类 100% ↔ 逐规范码也是 100%（让路失败 72/72、违规追越 48/48） | ✅ 自洽 |
| 归责对象正确 | 「目标船指错」计数 | ✅ **0 条**，即不只知道违规，还指对了是哪条船 |
| 漏报/误报清单 | 漏报 0 条、误报 0 条 | ✅ |
| 与对手的对照 | 我们的 `b`（对手对我们错）= 0，即**没有任何一条样本是对手判对我们判错** | ✅ |

## 六、V4 对比公平性验证

### V4.1 有没有让对手吃亏

| 可能的不公平 | 我们的做法 | 验证 |
|---|---|---|
| 不给对手调阈值 | 报 **oracle 阈值**（在评测集上调到最优），并明确标注这是**上界** | ✅ 表里的对手分数全是上界 |
| 让对手用错阈值方向 | 阈值方向双向试探 + 混淆矩阵对账（见 C1） | ✅ |
| 只给对手阉割的特征 | 对手拿到**会遇距离**这一关键几何量（这正是我们规则在用的量） | ✅ 唯一超过平凡线的 `proximity` 就是靠它 |
| 训练集不足 | 对手用全部真船正常窗拟合（无监督方法的规矩） | ✅ |
| 把对手调差 | 参数按文献惯例；特征给足（含会遇距离），并双向试探阈值方向 | ✅ |

### V4.2 有没有让我们占便宜

| 可能的便宜 | 我们的做法 |
|---|---|
| 我们偷偷调阈值 | **L1 没有可调阈值**，报了就报警，「部署即所得」——这是对我们最不利的口径 |
| 我们偷看答案 | 我们的判据是固定的物理/法规门槛，不依赖评测集 |
| 我们不用花成本 | 成本列如实报：0 次调用、0 token，**这也是事实**，不是作弊 |

### V4.3 特征级防泄漏

| 风险 | 做法 |
|---|---|
| 绝对位置反推海域 | 基线特征与我们的有监督筛查**一律不含绝对位置** |
| 生成器指纹偷分 | 刻意不把「报出航速与位置差分航速的差值」放进特征——那个差值在合成数据里是生成器指纹，会给对手偷分 |
| 标签泄漏 | 有监督筛查的标签派生特征被显式摘除（`benchmark/train_l2.py` 有专门的泄漏消融） |

### V4.4 对手在注入集上的表现是否符合机理

| 观察 | 解读 |
|---|---|
| 全部 8 个方法在注入集上 AUC < 0.5（7 个） | 有明确的机制解释（见结果说明 2.4），不是实现 bug |
| 唯一超过平凡线的 `proximity` | 它拿到的正是我们会遇规则在用的同一维几何量 → 说明特征给足了 |

> 这一条很重要：对手分数低必须是**可解释**的（任务与特征口径不同），而不是「我们把他们调差了」。

## 七、V5 结论稳健性验证（证伪测试）

| 证伪测试 | 设计意图 | 如果结论是假的会怎样 | 实测结果 |
|---|---|---|---|
| **门槛敏感度扫描** | 检验门槛是不是照测试集挑的 | 峰值会孤零零挂在某一个值上，换到邻近值就掉 | ✅ 5 个门槛峰值全部在生产取值处或其紧邻位置，两侧下降 → 通过 |
| **规则覆盖消融** | 检验级联的后两级是否有独立价值 | 若大模型也捞不回摘掉的那一类，则「级联」只是装饰 | ✅ 大模型捞回 100% / 20.8% → 有独立价值 |
| **全工作点披露** | 检验有没有 cherry-pick 好看的阈值 | 若只报一个最好的点 | ✅ 门控阈值扫描把 11 个工作点全部列出，包括最差的 |

**门槛扫描的保留意见（必须写进论文）**：其中 2 个门槛的峰值是**平台**而非尖点（减速门槛在 1/2/3 节上都是 100%）。平台的物理含义是「该门槛在此任务上不敏感」，**不等于**「门槛可以随便取」。论文里应写成「门槛位于一个宽的稳健区间内」。

## 八、V6 可复现性验证

| 验证项 | 做法 | 结果 |
|---|---|---|
| 单命令复现 | 每个实验一条命令（见设计文档第十一节） | ✅ |
| 断点续跑 | 所有长任务逐条/逐日落盘；关机重启同一条命令从断点继续 | ✅ **实际发生过一次断电**，一次性中断 4 个后台任务，重启后未丢任何已完成结果 |
| 随机性固定 | `temperature=0`、`seed=0`、划分种子固定（如负样本对半切用 20261014） | ✅ |
| 环境可写清 | 模型名与量化版本、`num_ctx`、并行度、模型目录全部记录在案 | ✅ |
| 产物可追溯 | 每个数字都能追到具体 JSON 文件；汇总脚本只读不重算 | ✅ |

**环境复现要点（三个实际踩过的坑）**：
1. Ollama 必须以 `OLLAMA_MODELS=E:\model` 启动，否则模型清单为空、返回 404。
2. 必须显式 `num_ctx=8192`，否则长提示被**静默截断**（不报错，只是模型看到半截轨迹）。
3. 并行度固定 `NUM_PARALLEL=2`（实测 3 路因显存溢出反而慢 15 倍）。

## 九、威胁效度分析（必须写进论文的 Limitations）

### 9.1 构念效度（测的是不是我们想测的）

| 威胁 | 说明 | 缓解 |
|---|---|---|
| 「注入的违规」是否等于「真实的违规」 | 注入场景的几何判据来自避碰规则，但真实违规含主观判断成分 | 已用独立参照实现校验几何；判据来源逐条对应到避碰规则条款 |
| F1 是否等价于「监管有用」 | 监管场景更看重可追溯与可复核 | 论文里另设「证据链 / 法规条款引用」一节讨论，不把 F1 当唯一标准 |

### 9.2 内部效度（有没有别的因素在捣乱）

| 威胁 | 状态 |
|---|---|
| 真值循环 | ✅ 已排除（真值由场景设计给定 + 独立参照实现回放校验） |
| 标签泄漏 | ✅ 已排除（无位置特征、无生成器指纹、标签派生特征有专门消融） |
| 缓存旧结果污染 | ✅ 已用指纹 + 事后核对 |
| 混合参数设置 | ✅ 已核对提示规模，确认无混用 |
| **单一随机种子** | ⚠️ 本批实验每个配置只跑了一个种子（采样温度为 0，本身确定性），**未做多种子重复** |

### 9.3 外部效度（能不能推广）

| 威胁 | 说明 |
|---|---|
| 注入源是单一水域 | 注入集的宿主船来自福建辖区的一段真实轨迹 |
| 船型/年份覆盖有限 | 未按船型、季节分层报告 |
| **这是最需要补充实验的方向**：多水域注入、跨年份交叉验证 |

### 9.4 统计结论效度

| 威胁 | 说明 | 缓解 |
|---|---|---|
| 评测集规模有限（240 条） | 置信区间较宽 | 已报配对自助置信区间，不掩盖宽度 |
| 不平衡下 McNemar 的解读 | 评测集不平衡时 b、c 都很大，p 值自然很小，但这只说明「错的地方不一样」，不等于质量差距大 | ✅ 已在显著性检验文档里明确写出这条读法提醒；质量差距以 **F1 差与它的置信区间**为准 |
| 注入集正负各半，与真实部署的正例占比不同 | F1 的绝对值不能直接外推到部署 | ✅ 同时报 AUC 与 @1%FPR 召回（这两个指标与正负比例无关） |
| 配对自助未做分层 | 未按违规类型分层重采样 | ⚠️ 已知简化 |

## 十一、最终结论

**R1–R8 需求对应的实验全部完成，且每条结论都通过了对应层级的验证**：

- 真值可溯源、与系统实现无关；
- 评测集未被构造成对自己有利；
- 计算结果有自校验，实际发现并修正了 3 类会导致错误结论的问题（预测方向、真值/预测混淆、成本漏计）；
- 对比条件对对手更有利（给上界、我们无阈值可调）；
- 通过门槛扫描、规则消融两项证伪测试；
- 全部实验可单命令复现、可断电续跑。

**唯一未通过项是「人工标注 GT」**，列为已知缺口并在文档中明确披露；应对方式是说明真值来源链条（场景设计 + 独立参照实现）并如实写出边界（注入场景 ≠ 真实违规）。
