# 智能体记忆系统设计方案

> 对应架构：三级级联架构（L1 加速器 → L2 ML 路由 → L3 LLM 判定）
> 
> 文档目标：为 LLM 判定层增加记忆能力，让系统越用越准，而不是每艘船都从零判断
>
> **现状对齐（2026-08-22）：** 三类记忆均已实现（`memory/`），但**当前检测管道（run.py/orchestrator）只使用 SessionMemory 与 ShipMemory**；PatternMemory（情景记忆）已实现但其「跳过 LLM」能力**不再用于检测管道**，仅服务于 ShipClaw 智能体个性化对话。详见 §四/§五。

---

## 一、为什么要加记忆

### 现有系统的问题

当前三级架构中，L3 LLM 每次被调用时都是**从零开始**：

```
CSV 里有 603 艘船 → LLM 跑了 603 次 → 每次都是独立判断
  → 同一艘船今天判了违规，明天再出现又得重新判
  → 禁渔区A 已经发现 5 起类似违规，第 6 艘船 LLM 不知道前面 5 艘的结论
  → 没有"惯犯"概念，没有"趋势"概念
```

### 加记忆后解决什么

| 场景 | 没记忆 | 有记忆 |
|------|--------|
| 同一 MMSI 再次出现 | 重新分析全部数据 | 直接调历史结论，只看新轨迹 |
| 同一区域出现同类行为 | 每次独立判断，结论可能不一致 | 复用已有模式，结论一致 |
| 单次运行 600 艘船 | 前 10 艘发现的新模式，后面 590 艘不知道 | 新模式自动传播给后续所有判断 |

## 二、三类记忆设计

### 2.1 船的记忆（Ship Memory）

**作用：** 记住每一艘船的历史行为，支持"惯犯识别"和"趋势跟踪"。

**存储：** SQLite（`data/memory/ship_memory.db`）—— ✅ 已实现（`memory/ship_memory.py`，`ShipMemory` 类）

**表结构：**

```sql
CREATE TABLE ship_memory (
    mmsi TEXT PRIMARY KEY,                    -- 船舶 ID
    first_seen TIMESTAMP,                     -- 首次出现时间
    last_seen TIMESTAMP,                      -- 最近一次出现时间
    total_appearances INT DEFAULT 1,          -- 累计出现次数
    
    -- 违规统计
    total_violations INT DEFAULT 0,           -- 累计违规次数
    violation_types TEXT,                      -- JSON: {"非法捕捞": 3, "闯入禁区": 1}
    
    -- 最近一次判定（完整留存上次 LLM 的 JSON 输出）
    last_judgment TEXT,
    last_assessment TEXT,                      -- 最终结论摘要
    last_confidence REAL,
    last_risk_level TEXT,
    last_recommended_action TEXT,
    
    -- 趋势分析
    risk_trend TEXT DEFAULT 'stable',          -- 'escalating' | 'stable' | 'improving'
                                               --  escalation: 违规次数在增加
                                               --  improving:   最近几次都是正常
                                               --  stable:      无变化
    
    -- 最近事件摘要（存最近 5 次的简短记录，用于 prompt 上下文）
    recent_events TEXT,
    
    -- 元数据
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**读写时机：**

```
处理每条船时：
  1. 查 ship_memory WHERE mmsi = ?
     → 有记录 → 把 last_assessment + risk_trend + recent_events 注入 prompt
     → 没记录 → 首次出现，不注入历史信息
  
  2. LLM 判定完成后：
      INSERT OR REPLACE INTO ship_memory 
      SET last_judgment=llm输出, 
          total_violations=total_violations+1(如果违规),
          last_seen=now()
```

**prompt 中的注入位置：**

```
【轨迹数据】
...

【事件摘要】
...

【该船历史记录】                          ← 从 ship_memory 查出来的
  上次出现: 2026-07-19
  累计出现: 5 次
  历史违规: 2 次（非法捕捞 2 次）
  最近一次结论: 禁渔区A低速捕鱼，已警告
  风险趋势: escalating（违规频率上升）
  最近事件: 
    · 2026-07-18 禁渔区A 警告
    · 2026-07-15 港口区 正常通过

请综合历史记录和当前数据做出判断
```

**适用场景：**

- 同一艘船在多个 CSV 文件中反复出现
- 需要识别"惯犯"（累计违规 3 次以上）
- 需要判断行为趋势（首次违规 vs 屡教不改）

### 2.2 情景记忆（Pattern Memory）

**作用：** 记录"某种场景下 LLM 是怎么判的"，下次出现高度相似的场景时直接复用，不用调 LLM。

> **⚠️ 现状（2026-08-22）：** `memory/pattern_memory.py`（`PatternMemory`，SQLite `data/memory/pattern_memory.db`）已实现，包含 `find_match`（余弦 ≥0.85）/ `can_skip_llm` / `get_stable_patterns` 等方法，但**检测管道已不再使用它**（run.py/orchestrator.py 注释明确：PatternMemory 不再用于检测管道，不靠它跳过 LLM）。它当前服务于 ShipClaw 智能体（个性化对话），不再做「加速器检测时跳过 LLM 调用」。

**存储：** SQLite 表（`data/memory/pattern_memory.db`），特征向量用 BLOB 存

**表结构：**

```sql
CREATE TABLE pattern_memory (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    
    -- 场景标识
    zone TEXT NOT NULL,                        -- 区域 ID
    scenario TEXT NOT NULL,                    -- 行为类型（fishing/speeding/intrusion）
    
    -- 特征签名（由加速器输出的 28 维核心特征中提取的场景指纹）
    signature BLOB,                            -- 特征向量的二进制表示
    feature_hash TEXT,                         -- SHA256(signature)，用于快速索引
    
    -- LLM 对该场景的历史判定
    typical_judgment TEXT,                     -- 'violation' | 'normal'
    typical_violation_type TEXT,
    typical_confidence REAL,
    llm_conclusion_summary TEXT,              -- LLM 对这类场景的结论摘要
    
    -- 统计
    occurrence_count INT DEFAULT 1,            -- 该场景出现次数
    first_occurrence TIMESTAMP,
    last_occurrence TIMESTAMP,
    judgment_consistency REAL,                 -- 多次判定的结果一致率
    
    -- 如果该模式与某种规则强相关，记录规则引用
    related_regulations TEXT,                  -- JSON: ["渔业法第23条", "渔业法第25条"]
    
    UNIQUE(zone, scenario, feature_hash)
);
```

**读写时机（设计原稿）：**

```
处理每条船时：
  1. 加速器2输出特征向量 → 计算 feature_hash
  2. 查 pattern_memory WHERE zone=? AND scenario=? AND feature_hash=?
     → 命中且 occurrence_count >= 3（模式稳定）
       且 judgment_consistency >= 0.9
       → 直接复用典型结论，跳过 LLM 调用
     → 命中但条件不满足
       → 正常调 LLM，但把历史结论注入 prompt 做参考
     → 未命中
       → 正常调 LLM

  3. LLM 判定完成后：
     如果 signature 与已有记录相似度 > 0.85：
       → 更新已有记录：occurrence_count+1，更新 consistency
     如果 signature 与所有记录相似度 < 0.7：
       → 插入新记录
```

> ⚠️ **当前实际状态：** 上述「跳过 LLM 调用」逻辑**未接入检测管道**（`run.py` / `orchestrator.py` 已停用）。PatternMemory 仅在 ShipClaw 智能体侧被使用。若未来恢复「检测时跳过 LLM」，需重新把 `can_skip_llm` 接到 `orchestrator._llm_with_memory()` 前。

**这个表的实际效果：**

基于你的实验数据（603 艘船，置信度 >= 0.9 的 482 艘只有 1 艘分歧），情景记忆能把"置信度 >= 0.9 且场景已出现过 3 次以上"的船直接走记忆、不调 LLM。

**粗略估算：**

```
603 艘船：
  ├── 约 400 艘是"普通通过"（normal 高置信度）
  │   → 第1次：调 LLM，写入 pattern_memory
  │   → 第2-3次：调 LLM，更新 consistency
  │   → 第4次起：直接复用，跳过 LLM
  │
  ├── 约 100 艘是"明显违规"（obvious_issue 高置信度）
  │   → 同理，几种典型违规模式很快固化
  │
  └── 约 100 艘是模糊 case（中等/低置信度）
      → 每次调 LLM，存入记忆但不跳过
```

运行 3-5 次后，pattern_memory 中有足够样本的稳定模式可以达到 **30-50% 的 LLM 调用节省**，且节省的都是"已经判过几十次、结果一致的重复场景"。

### 2.3 会话记忆（Session Memory）

**作用：** 单次运行（一次 python run.py）中，前几艘船的发现能被后面的船利用。

**存储：** 进程内 Python 对象，运行结束即丢弃

**实现：**

```python
class SessionMemory:
    """
    一次 run.py 执行过程中的短期记忆。
    跑完就丢，不需要持久化。
    """
    
    def __init__(self):
        # 本次运行中发现的新模式
        # { (zone, scenario): { "count": int, "conclusion": str, "llm_summary": str } }
        self.emerging_patterns = {}
        
        # 每个区域当前的总体状态
        # { zone_id: { "ships_seen": int, "violations": int, "latest_summary": str } }
        self.zone_status = {}
        
        # 最近 50 艘船的判定结果（用于趋势判断）
        self.recent_decisions = []
        
        # 本次运行已见过的 MMSI（避免同一批次中重复加载历史）
        self.seen_mmsi_in_session = set()
    
    def record_llm_result(self, mmsi: str, zone: str, scenario: str, llm_result: dict):
        """记录一条 LLM 判定结果"""
        # 更新 emerging_patterns
        key = (zone, scenario)
        if key not in self.emerging_patterns:
            self.emerging_patterns[key] = {
                "count": 0,
                "violation_count": 0,
                "conclusion": None,
                "llm_summary": None
            }
        self.emerging_patterns[key]["count"] += 1
        if llm_result.get("violation_detected"):
            self.emerging_patterns[key]["violation_count"] += 1
        self.emerging_patterns[key]["llm_summary"] = llm_result.get("final_assessment", "")
        
        # 如果该模式出现 >= 3 次且多数判定为违规 → 标记为"已确认模式"
        p = self.emerging_patterns[key]
        if p["count"] >= 3:
            if p["violation_count"] / p["count"] > 0.66:
                p["conclusion"] = "违规"
            else:
                p["conclusion"] = "正常"
        
        # 更新 zone_status
        if zone not in self.zone_status:
            self.zone_status[zone] = {"ships_seen": 0, "violations": 0}
        self.zone_status[zone]["ships_seen"] += 1
        if llm_result.get("violation_detected"):
            self.zone_status[zone]["violations"] += 1
        
        # 更新 recent_decisions
        self.recent_decisions.append({
            "mmsi": mmsi,
            "violation": llm_result.get("violation_detected"),
            "risk": llm_result.get("risk_level"),
            "time": datetime.now()
        })
        if len(self.recent_decisions) > 50:
            self.recent_decisions.pop(0)
        
        self.seen_mmsi_in_session.add(mmsi)
    
    def get_prompt_context(self, mmsi: str, zone: str, scenario: str) -> str:
        """生成一段文字，注入到下一艘船的 prompt 中"""
        parts = []
        
        # 本次运行已确认的模式
        confirmed = [(k, v) for k, v in self.emerging_patterns.items() if v["conclusion"]]
        if confirmed:
            parts.append("【本次运行已发现模式】")
            for (z, sc), v in confirmed[:3]:
                parts.append(f"  {z} {sc}: {v['conclusion']}（已出现 {v['count']} 次）")
        
        # 该区域当前状态
        if zone in self.zone_status:
            zs = self.zone_status[zone]
            if zs["ships_seen"] > 1:
                parts.append(f"【{zone} 状态】")
                parts.append(f"  已处理 {zs['ships_seen']} 艘船，违规 {zs['violations']} 艘")
        
        # 该船是否在本轮出现过
        if mmsi in self.seen_mmsi_in_session:
            parts.append(f"【注意】该船 MMSI 在本轮已出现过一次，请关注其轨迹是否匹配上次的判定")
        
        return "\n".join(parts)
```

**在 run.py 中的用法：**

```python
# 初始化（一次运行只创建一次）
session_memory = SessionMemory()

# 逐船处理循环中
for ship in ships:
    # ... 加速器处理 ...
    # ... ML 路由 ...
    
    # LLM 调用前：注入会话记忆
    session_context = session_memory.get_prompt_context(ship.mmsi, zone, scenario)
    prompt = f"{base_prompt}\n{session_context}"
    
    llm_result = llm.analyze(prompt=prompt)
    
    # LLM 调用后：记录本次结果
    session_memory.record_llm_result(ship.mmsi, zone, scenario, llm_result)
```

## 三、三种记忆的协作流程

```
启动 run.py
  │
  ├── 初始化 SessionMemory（空 dict，跑完丢弃）
  │
  └── 逐船循环:
        │
        ├── ① 查 ship_memory（持久化）
        │    → 该船有前科？注入历史记录
        │
        ├── ② 查 pattern_memory（持久化）
        │    → 该场景已稳定？直接复用，跳过 LLM
        │
        ├── ③ 查 SessionMemory（进程内）
        │    → 本轮已发现模式？注入上下文
        │
        ├── LLM 判定
        │
        └── ④ 写入三种记忆
             ├── ship_memory: 更新该船记录
             ├── pattern_memory: 更新/新增场景模式
             └── SessionMemory: 记录本轮发现
```

### 三种记忆的分工

| 维度 | ship_memory | pattern_memory | session_memory |
|------|-------------|----------------|----------------|
| **范围** | 单艘船 | 一类场景 | 一次运行 |
| **生命周期** | 永久 | 永久 | 进程结束即销毁 |
| **存什么** | 船的履历 | 场景的典型结论 | 本轮的新发现 |
| **读时机** | 同一 MMSI 再来时 | 同一场景再次出现时 | 每艘船处理前 |
| **写时机** | 每艘船判定完 | 每艘船判定完 | 每艘船判定完 |
| **存储** | SQLite / PostgreSQL | SQLite | Python dict |
| **节省什么** | 重复查同一条船的历史 | 重复判同一类场景 | 本轮发现的模式跨船传播 |
